# 한국어 Ipsum 대규모 기능 검증 원고

[`large-5x.md`](large-5x.md), 검증된 [`large-5x.ir.json`](large-5x.ir.json),
그림 리소스 [`image.png`](image.png)를 함께 보관합니다. v0.3.0 / IR 0.3용입니다. 아래 실제 출력·시간 기록은 각 검증 당시 빌드와 템플릿의 결과입니다.

## 본문 규모

2026-10-05 작성 당시, 생성 HWP까지 검증한 원고 중 텍스트 분량이 가장 컸던
`artifacts/tables/long.md`를 기준으로 합니다. 이 원고는 본문 74행 표였고,
한글 출력 6쪽을 확인했습니다. 기준 원고의 SHA-256은 다음과 같습니다.

```text
e12cbb64f95626239f8a5dc8908a3af2b36ec6241e2bdb41ab96a79c8b373bf1
```

규모 단위는 공백으로 구분한 어절입니다. 기준 IR의 제목·표 셀·캡션·출처에
담긴 텍스트가 2,231어절이므로, Ipsum 본문을 정확히 5배인 **11,155어절**로
만들었습니다. 이 118문단은 기능 추가 후에도 문자와 순서를 그대로 유지합니다.
YAML·제목·목록·표·박스·캡션·출처·각주의 추가 텍스트는 이 본문 수에 포함하지
않으므로, 원고 전체 텍스트는 11,155어절보다 많습니다.
쪽수는 표·그림·장 표지와 서식에 따라 달라져 5배 기준으로 사용하지 않습니다.

| 항목 | 규모 |
| --- | ---: |
| 기존 Ipsum 본문 | 11,155어절 / 118문단 / 50,541자 |
| 장 / 절 | 5장 / 20절 |
| 1~6단계 헤딩 | 각각 5 / 20 / 20 / 10 / 2 / 2개 |
| 그림 / 표 / 박스 | 29 / 39 / 14개 |
| 글머리 / 번호 목록 항목 | 278 / 26개, 최대 깊이 6 |
| 각주 삽입 위치 | 66개, 정의 64개 중 2개를 재사용 |
| 번호 상호참조 | 그림 18개 / 개요 18개 |
| 표 본문 행 / 전체 셀 | 284행 / 1,090셀, 빈 셀 39개 |
| IR 루트 블록 | 462개 |

본문은 저장된 후보 데이터를 사용하는 생성기로 작성하고, 문단 순서를 유지해
장과 절에 배분했습니다. 다음 명령은 같은 어절 수의 새 본문을 표준 출력으로 만듭니다.
기능 배치까지 자동 생성하는 명령은 아니며, 난수를 사용해 문장이 매번 달라집니다.
동일한 원고를 비교할 때는 동봉된 파일을 사용하십시오.

```powershell
pwsh -NoProfile -File .\tools\development\generate-korean-lorem.ps1 11155
```

## AURI 예시 보고서의 기능 빈도

`reference/auri/auri 연구보고서 편집양식(2026)`의 고유한 4종 HWP를 집계했습니다.
기본은 Section3, 나머지는 Section3·4의 참고문헌 전 본문을 사용하고,
표지·요약·차례·참고문헌·부록을 제외했습니다. 동일한 기본 보고서 복사본은
중복 집계하지 않았습니다. 원본 파일의 SHA-256은
[생성기의 출처 주석](../../tools/development/generate-korean-lorem.ps1)에 있습니다.

| 예시 보고서 | 본문 어절 | 그림 | 표 | 박스 | 각주 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 기본 | 2,200 | 4 | 8 | 1 | 36 |
| 정책 | 2,411 | 4 | 10 | 3 | 26 |
| 일반 | 4,823 | 13 | 10 | 1 | 4 |
| 현안 | 2,128 | 9 | 12 | 9 | 2 |
| 합계 | 11,562 | 30 | 40 | 14 | 68 |

그림과 표는 실제 캡션의 `[그림]`·`[표]`로 구분해 제목·간지·머리말의 레이아웃
표를 제외했습니다. 박스는 박스 스타일을 포함한 본문 표 개체 단위로 세었고,
각주는 실제 각주 제어문자를 세었습니다. 이 비율을 11,155어절에 적용해
그림 29개·표 39개·박스 14개·각주 66개를 5개 장에 분산했습니다.

본문의 실제 글머리 문단 288개는 278개로 환산했습니다. Markdown 목록 묶음과
HWP 문단을 정확한 1:1 대응으로 보지는 않습니다. 보고서에는 번호 문단이 8개뿐이지만,
이 원고는 6단계와 혼합 중첩을 두 번씩 시험하기 위해 번호 항목을 26개로 늘렸습니다.
예시 보고서에서 native Crossref 필드는 발견되지 않아 상호참조도 비율 환산 대신
일부 절의 검증 사례로 배치했습니다. 출처 생략과 캡션 생략은 드물게 넣었습니다.

기능 밀도 계산은 짧은 소제목·요약형 글머리를 포함한 475문단을 사용합니다.
Ipsum 언어 후보 생성에 사용한 402문단·11,060어절과 집계 목적·범위가 다릅니다.
이 집계는 HWP OLE·압축 레코드를 읽은 결과이며 예시 보고서의 시각 검토는 아닙니다.

## 포함한 기능과 경계 사례

- YAML: title·subtitle·author 목록·한국어 date·publisher·임의 md2hwp-* 키.
  date-meta는 `2026-10-05`로 파생되며, heading1-start는 3으로 시작합니다.
- 본문: 굵게·기울임·중첩 강조, 일반 줄바꿈과 강제 줄바꿈, Unicode,
  표시문 링크·참조형 링크·URL·이메일·자동 링크 구문.
- 목록: 글머리·번호, tight·loose, 다문단 항목, 시작 번호 1·3,
  6단계와 양방향 혼합 중첩. 입력의 `.`·`)`는 출력 번호 모양을 결정하지 않으며
  템플릿의 번호 서식을 따릅니다.
- 박스: 제목 있는/없는 원문, 제목 뒤 빈 줄·공백 줄, 본문 빈 줄·들여쓰기·
  Markdown 표기의 리터럴 처리, 출처 있는/없는 경우.
- 그림: 같은 PNG를 재사용하고 그림 ID·강조한 캡션·출처 유무를 시험합니다.
  image.png는 기존 all-features-twice 리소스를 바이트 그대로 복사한 파일입니다.
- 표: 위쪽 `Table:`·`table:`·`:` 캡션, 캡션과 출처의 독립적인 생략,
  default·left·center·right 정렬, 빈 셀·강조·링크·각주·참조.
  4~6행 표와 48행 표 두 개로 짧은 표와 긴 표를 함께 제공합니다.
- 각주: 본문·heading3·목록·표 셀, 다문단·강조·링크·강제 줄바꿈·참조,
  같은 정의 재사용. 머리말로 복제되는 heading1에는 각주를 넣지 않습니다.
- 참조: 그림·heading2, 전방·후방·장 사이, 빈 표시문·참조형 링크·한글 ID와
  URI 이스케이프, 본문·헤딩·목록·표 셀·각주 안의 참조.

한 YAML에 동시에 넣을 수 없는 author 단일 문자열과 여러 날짜 입력 형식은
기존 [메타데이터 예제](../metadata/)와 테스트 fixtures에서 다룹니다.
현재 pipe_tables Markdown에는 표 셀의 강제 줄바꿈을 표현하는 성공 문법이 없어
이 원고에는 넣지 않았습니다. IR·직접 Pandoc JSON의 셀 LineBreak는 별도로 지원합니다.
원고 박스의 탭 입력은 현재 Pandoc에서 공백으로 정규화되므로 탭 출력 보존의
검증 자료로 사용하지 마십시오.

## 실행과 검증 범위

저장소 루트에서 IR을 다시 생성·검증할 수 있습니다.

```powershell
.\target\release\md2hwp.exe md2ir .\examples\korean-lorem\large-5x.md --force
```

현재 지원 Markdown 문법의 해석, IR 0.3 검증, 기존 본문의 보존과 기능별 개수를
확인했습니다. 2026-10-05에는 한글 변환·저장·재열기 구조 검증을 통과하고 전체 쪽
모음과 대표 쪽의 시각 점검을 수행했습니다. 세부 결과와 발견 사항은 아래에 기록합니다.
한글 문서를 닫은 뒤 다음 명령으로 HWP를 생성할 수 있습니다.

```powershell
.\target\release\md2hwp.exe .\examples\korean-lorem\large-5x.md --template .\templates\template.hwp
```

이 명령은 사용자 `target/release/template.hwp` 대신 추적 템플릿을 명시합니다.
추적 템플릿의 장·절 블록, 소속 절 반복, once, 목록·각주·개체·참조 원형을 사용합니다.
메타데이터의 실제 치환은 `meta:*` 태그, 날짜 표시 서식은 date-meta의 `fmt`,
박스 제목 분리는 `slot:box.title`이 있는 템플릿에서만 작동합니다. 2026-10-05 시험 당시 템플릿에는
meta 태그와 box.title 슬롯이 없어 메타데이터는 IR에 남고 박스 `제목:` 줄은 원문으로
표시됐습니다. v0.3.0용 편집 템플릿에는 `meta:title`과 `slot:box.title`이 있으며,
문서 제목 치환과 박스 제목 분리를 지원합니다. [메타데이터](../../docs/yaml-variables.md)·
[박스 제목](../../README.md)의 템플릿 규칙을 참고하십시오.
생성 HWP는 Git에서 제외하고 원고·IR·이미지는 추적합니다.

```text
532962b281900e3f1fd877b950aa3c1905402f9d921caa9c54d7335a9305c549
```

저장 XML을 독립 집계해 표 39개의 142mm 폭, 본문 284행, 출처 37행의 병합·투명
서식과 반복 머리행 설정을 확인했습니다. 상호참조 36개의 대상·표시값·로컬 FieldId
쌍과 고유 InstId도 확인했으며, 미처리 `md2hwp` 태그는 없습니다. 저장 과정에서
일부 문단 모양 번호는 재배치됐지만, 번호를 해석한 실제 서식은 템플릿과 같습니다.

111쪽을 20쪽 단위의 모음 이미지로 보고, 물리 쪽 5·7·8·10·31·32·33·62·64·
83·85·86·111을 원래 크기로 확인했습니다. 두 48행 표는 각각 30~33쪽과 83~86쪽에
걸쳐 이어지고, 반복 머리행·마지막 출처·표 셀 각주가 표시됩니다. 그림·박스·출처,
중첩 목록과 여러 각주가 놓인 표본에서 겹침이나 잘린 본문은 발견하지 못했습니다.
이는 모든 길이·서식 조합의 배치 안전성을 보장하지 않습니다.

시각 점검에서 다음 사항도 확인했습니다.

- 7쪽 하단에는 첫 표의 캡션과 머리행만 남고 본문 행은 8쪽으로 넘어갑니다.
  반복 머리행과 데이터는 유지되지만, 머리행과 첫 본문 행을 함께 배치하는 처리는
  최초 변환 당시에는 별도로 하지 않았습니다.
- 본문 네 곳의 `**[개요 참조](#...)**는`은 CommonMark 단계에서부터 별표가
  일반 텍스트로 해석되어, 출력에도 `**1.**는` 같은 표기가 남습니다. HWP 출력기가
  별표를 추가한 것이 아니며, 이 문법의 강조 적용을 검증했다고 보지 않습니다.
- 64쪽의 도시 이모지는 네모로 표시됩니다. IR과 저장 XML에는 원래 Unicode가
  남아 있으므로 서체·한글의 글리프 표시 제약으로 추정합니다.

앞의 빈 쪽 2개, 캡션·장 표지의 literal `#`, 머리말의 placeholder 표기는 현재
템플릿 내용과 쪽 나눔 설정을 그대로 따른 결과입니다. 메타 치환·박스 제목 분리는
앞서 설명한 템플릿 조건 때문에 이번 HWP에서 시험되지 않았습니다.

스타일 적용과 그림·박스 복제 검증이 문서 전체 HWPML을 반복해서 내보내고
파싱하는 경로를 확인했습니다. 큰 원고의 성능 개선 후보이며, 시간 비중을 분리
측정하거나 최적화하지 않은 단계의 기록입니다. 이후의 계측 결과는 아래에 기록합니다.
재열기 XML·실행 로그·쪽 PNG·모음 이미지는
ignored `artifacts/large-manuscript/`에 보관하고 생성 HWP는 원고 옆에 둡니다.

## 시각 문제만 모은 작은 재현 원고

[`layout-issues.md`](layout-issues.md)와 [`layout-issues.ir.json`](layout-issues.ir.json)은
위 대규모 시험의 세 가지 시각 문제만 모은 축약 원고입니다. 현재 원고는 1,461바이트이며,
참조 대상 제목·문제/대조 문장·Unicode 문장·위치 조정 19줄·본문 3행 표 하나로 구성합니다.
외부 그림 리소스는 필요하지 않습니다.

저장소 루트에서 현재 Release 빌드로 실행합니다.

```powershell
.\target\release\md2hwp.exe .\examples\korean-lorem\layout-issues.md --template .\templates\template.hwp
```

2026-10-05, 같은 한글 2020 11.0.0.9136과 추적 템플릿에서 변환·저장·재열기 검증을
통과했습니다. 결과 `layout-issues.output.hwp`는 20,480바이트, 물리 5쪽입니다.
실제 본문은 2쪽이며, 앞의 빈 쪽 2개와 장 표지 1쪽은 템플릿 설정을 그대로 따릅니다.

강조 문제는 CommonMark/Pandoc AST에서부터 일반 텍스트인 별표로 넘어옵니다.
대조 문장은 IR에서 `strong`으로 파싱되지만, 번호 상호참조의 실제 글자 서식은
당시 참조용 템플릿 원형을 따랐습니다. v0.3.0에서는 원고 위치의 서식을 따릅니다.
이모지는 표시 제약만 재현했으며 정확한 원인은 확정하지 않았습니다.

위치 조정용 문단의 19줄은 Markdown의 줄 끝 공백 두 개로 강제 줄바꿈한 것입니다.
이 줄 수는 현재 템플릿의 용지·서식에 맞춘 재현 조건이므로, 다른 템플릿이나 서체 환경에서는
표의 분리 위치가 달라질 수 있습니다. 표 캡션의 `num:heading1`을 채우기 위해 장 제목을 유지합니다.
표는 4열·반복 머리행·본문 3행·병합 출처 1행이며, 실제 개요 상호참조는 2개입니다.

원래 대규모 원고·IR 및 두 템플릿은 변경하지 않았습니다. 재현용 원고·IR은 추적하고,
생성 HWP와 XML·쪽 PNG·실행 로그(`artifacts/layout-issues/`)는 Git에서 제외합니다.

## 강조 경계 수정

최초 변환 기록의 별표 잔존은 CommonMark의 닫는 강조 구분자 규칙 때문입니다.
`**[개요 참조](#section-1-1)**는`에서는 닫는 `**` 앞이 문장부호 `)`이고
뒤가 한글 조사여서 강조가 닫히지 않습니다. Pandoc JSON은 `Strong` 대신
일반 `Str("**")`, `Link`, `Str("**는")`를 전달하며, IR도 이 별표를 보존합니다.
[CommonMark 0.31.2의 강조 규칙](https://spec.commonmark.org/0.31.2/#emphasis-and-strong-emphasis)을 따르는 동작입니다.

`large-5x.md`의 해당 네 곳을 `**[개요 참조](#section-1-1)는**` 형태로
수정했습니다. 조사까지 강조 안에 넣으므로 불필요한 공백 없이 작성할 수 있습니다.
IR을 재생성하여 각 위치가 `strong` 안의 `cross_reference`와 `text("는")`로
바뀌는지 확인했습니다. Ipsum 본문 118문단의 텍스트·순서와 다른 기능은 유지합니다.

작은 재현 원고는 잘못 작성한 문제 문장을 그대로 두고, 대조 문장만 같은 방식으로
수정했습니다. 문제·수정 문장을 함께 남겨 CommonMark 경계 차이를 확인합니다.
이 검증 당시 참조 번호 자체의 글자 서식은 템플릿의 `ref.heading.number` 원형을 따랐으므로,
`strong`으로 파싱된다는 사실만으로 번호 글꼴의 굵기가 바뀐다고 보지 않습니다.
여기서의 검증은 Pandoc AST·IR에 대한 것이며, 수정 후 한글의 저장·재열기와
시각 검증 결과는 별도로 기록합니다. 이모지 문장과 글꼴은 변경하지 않았습니다.

## 표 머리행 보정과 수정 문법의 실제 검증

2026-10-06에 Release 빌드와 추적 템플릿으로 작은 재현 원고를 다시 변환했습니다.
`layout-issues.fixed.output.hwp`는 최종 저장·재열기 구조 검사와 실제 셀 위치 검사를
통과했습니다. 물리 4쪽 하단에 남던 캡션·머리행을 제거하고, 5쪽(표시 번호 3)에
캡션·머리행·본문 3행·출처가 함께 배치되는 것을 쪽 이미지로 확인했습니다.
머리행 4셀과 첫 본문 행 4셀의 시작은 모두 표시 쪽 번호 3, 1단입니다.
문제 문장의 잘못된 CommonMark 별표는 재현용으로 그대로 남고, 조사까지 강조 안에
넣은 대조 문장은 별표 없이 표시됩니다. 이모지 원문과 글꼴은 변경하지 않았으며,
이모지의 네모 표시도 그대로입니다.

표 보정은 번호 참조를 완성한 뒤 실제 쪽·단 위치를 읽어, 머리행만 남는 생성 표의
앵커에만 쪽 나눔을 추가합니다. 긴 표의 반복 머리행과 이후 행 나눔은 유지합니다.
전체 표·셀·캡션 서식을 바꾸지 않으며, 저장·재열기 뒤에도 위치를 다시 확인합니다.
세부 동작과 제한은 [표 설명](../../docs/tables.md)에 있습니다. 작은 원고의 원래
결과는 `layout-issues.output.hwp`로 보관하고 수정 결과를 별도 파일로 둡니다.
XML·쪽 PNG·셀 위치 JSON·실행 로그는 ignored `artifacts/table-header-fix/`에 보관합니다.

시간 계측만 추가한 대규모 변환은 634.615초였고, 전체 XML 내보내기 855회가
485.466초를 차지했습니다. 측정 조건·단계별 시간·단축 후보는
[대규모 문서 성능 측정](../../docs/render-performance.md)에 정리했습니다.
최적화의 효과를 측정한 값은 아닙니다.

같은 날 수정 빌드로 대규모 원고도 변환하여 최종 결과 `large-5x.output.hwp`를
교체했습니다. 종료 코드 0, 변환 779.527초(쪽 이미지 출력 제외),
4,966,400바이트·물리 112쪽입니다. 머리행이 고립된 표 7개를 보정했으며,

확인했습니다. 입력 MD·IR·이미지·추적 템플릿·사용자 Release 템플릿의 해시는
이 실행 전후 동일합니다.

독립 XML 집계에서 그림 29개·표 39개·박스 14개·각주 66개·실제 번호 참조 36개,
