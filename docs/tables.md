# 표

Markdown 입력은 `commonmark+yaml_metadata_block+footnotes+attributes+implicit_figures+pipe_tables`를 사용합니다.
CommonMark 표준에는 표가 없으며, `pipe_tables` 확장으로 머리행과 본문 행을 읽습니다.
IR 0.3은 열 정렬, 머리행, 본문 행, 선택적인 캡션과 출처를 보존합니다.

## 원고

샘플 원고에서는 캡션을 표 위에, 출처를 표 아래에 둡니다.

```markdown
Table: 지역별 현황

| 구분 | 조사일 | 설명 |
| :--- | :---: | --- |
| A | 2026-10-01 | 대상지의 현황을 설명합니다. |
| B | 2026-10-02 | **주요 변화**와 *부연 설명*입니다. |

출처: 작성자 작성.

: 출처 없는 표

| 항목 | 결과 |
| --- | ---: |
| 대상 수 | 12 |
| 비고 | |
```

`Table: 제목`, `table: 제목`, `: 제목` 문단을 표 바로 앞이나 뒤에 사용할 수 있습니다.
접두어 뒤에는 공백과 비어 있지 않은 내용이 필요합니다. 표와 캡션은 빈 줄로
분리하여 별도 문단으로 작성합니다. 이 문법은 Pandoc Markdown의 `table_captions`와
호환되지만, CommonMark 입력에서는 일반 문단으로 넘어오므로 md2hwp가 인접한 표에
연결합니다. `table_captions` 확장을 CommonMark 입력에 활성화하는 방식은 아닙니다.
캡션 접두어는 출력에서 제거합니다. 캡션의 원고 위치를 IR에 보관하지 않으며,
실제 출력 위치는 템플릿의 한글 캡션 설정을 따릅니다.

표 앞뒤에 캡션이 모두 있거나, 두 표 사이의 캡션이 양쪽 표에 인접하면 오류입니다.
두 표 사이의 캡션이 모호한 경우에는 중간에 일반 본문 등 다른 블록을 둡니다.
이미 Pandoc JSON의 표 캡션으로 들어온 내용도 한 문단이면 사용할 수 있지만,
인접한 캡션 문단을 중복해서 제공할 수 없습니다.

`출처: 내용`은 표 바로 다음의 별도 문단에 둡니다. 표 아래에 캡션을 두었다면
그 캡션 다음에 출처를 둡니다. 출처가 없으면 출력 표의 출처 행 전체를 생략합니다.
캡션이 없으면 한글 캡션 자체를 생략하며, 출처 행과는 독립적으로 처리합니다.

셀은 빈 값이나 한 개의 일반 문단을 지원합니다. 굵게·기울임·링크·강제 줄바꿈,
참조형 각주와 기존 그림·개요 번호 상호참조를 셀 안에 사용할 수 있습니다.
링크는 서식 있는 표기 텍스트로 출력합니다. 캡션과 출처에서는 굵게·기울임·링크를
사용할 수 있지만 각주와 번호 상호참조는 지원하지 않습니다.

열 구분선의 `:---`, `:---:`, `---:`는 왼쪽·가운데·오른쪽 정렬을 지정합니다.
콜론이 없는 열은 템플릿 샘플 문단의 정렬을 유지합니다. CommonMark 입력의 `pipe_tables`는
구분선의 `-` 개수로 열 너비를 JSON에 전달하지 않으므로 그 길이는 열 너비에 영향을
주지 않습니다.

## 템플릿

다음 선언을 `begin:template`과 `end:template` 사이에 각각 하나씩 둡니다.
표를 사용하지 않는 원고에도 표 설정과 원형은 필요합니다.

```text
{{md2hwp:table.width-mm:142}}
{{md2hwp:begin:table}}
[실제 한글 표가 있는 문단]
{{md2hwp:end:table}}
```

`table.width-mm`는 표 전체의 고정 폭을 mm로 지정합니다. 기본 새 템플릿은 142mm이며,
0보다 큰 십진수를 사용합니다. 소수점은 `.`으로 씁니다. 설정은 `begin:table` 앞의
독립 문단에 두고, 경계 두 문단 사이에는 실제 한글 표 하나가 붙은 문단 하나만 둡니다.
대괄호 설명을 글자로 입력하는 것이 아니라 실제 표 개체를 넣습니다.

원형은 정확히 **3행·1열**로 만들며, 각 셀에는 다음 슬롯 문단을 하나씩 둡니다.

| 원형 위치 | 셀의 내용 | 가져올 서식 |
| --- | --- | --- |
| 첫 행 | `{{md2hwp:slot:table.header}}` | 원고의 머리행 전체에 적용할 셀·문단·글자 서식 |
| 중간 행 | `{{md2hwp:slot:table.content}}` | 원고의 본문 행·열마다 반복할 서식 |
| 마지막 행 | `출처: {{md2hwp:slot:table.source}}` | 선택적인 출처 행의 서식과 접두어 |

첫 행과 중간 행의 슬롯은 문단 전체를 차지해야 합니다. 마지막 셀의 슬롯 앞뒤에는
출처 접두어 등 고정 문구를 둘 수 있습니다. 마지막 셀은 모든 테두리·배경·빗금 등을
없애 투명하게 만듭니다. 생성할 때 모든 열을 병합한 마지막 행이 되며, 출처가 없으면
행 자체를 만들지 않습니다. 원형 표의 행 높이·열 너비·샘플 내용은 생성 크기를
정하지 않습니다. 머리행과 본문 행의 셀 여백·테두리·배경·문단·글자 서식은 가져옵니다.

표 제목은 마지막 행에 넣지 않습니다. 실제 한글 표의 **캡션** 안에 한 문단을 두고,
원하는 위치에 `{{md2hwp:slot:table.caption}}`을 넣습니다. 다음은 캡션 문단의 예입니다.

```text
[표 {{md2hwp:num:heading1}}-<한글 표 자동번호>] {{md2hwp:slot:table.caption}}
```

`<한글 표 자동번호>`는 설명이며, 글자로 입력하지 않습니다. 한글의 실제 **표 자동번호**
제어를 정확히 하나 넣습니다. 장 번호는 선택적인 `num:heading1`로 현재 표의 장을
표시하고, 번호 앞뒤의 문구와 글자 서식은 템플릿에서 정합니다. 캡션 슬롯은 정확히
하나 필요합니다. 캡션 안에는 다른 제어문자나 쪽·단 나눔을 넣지 않습니다.

한글의 캡션 위치·간격·정렬 등 네이티브 설정을 가져옵니다. 새 템플릿은 표 위에
캡션을 둡니다. 표 번호는 한글의 실제 자동번호이며 문서 시작번호, 구역 시작번호와 템플릿의
새 번호 제어를 따릅니다. 그림 번호처럼 장마다 새 표 번호를 자동 삽입하는 기능은 없습니다.
장 번호 태그와 표 자동번호는 별도로 처리합니다.

표의 머리행 반복과 페이지 나눔도 템플릿 표 설정을 가져옵니다. 새 템플릿은 머리행
반복과 셀 단위 쪽 나눔을 설정하고, 표의 ‘글자처럼 취급’을 해제합니다.
‘글자처럼 취급’이 켜진 표는 긴 내용이 쪽 사이로 나뉘지 않아 잘릴 수 있습니다.
머리행을 제외한 원고의 행 수와 모든 열 수는 원고에서 결정하며, 표 원형의 크기는 무시하고 복사한 표를 재구성합니다.

## 내용에 맞춘 열 너비

한글의 열 너비 자동 배분 명령에 의존하지 않고, md2hwp가 내용을 측정해 열 너비를
계산합니다. 설치된 Windows TrueType/OpenType 글꼴의 측정 기능으로
머리행과 본문 셀의 서체·글자 크기,
굵게·기울임·장평·자간을 반영합니다. 셀 여백과 문단 여백·들여쓰기를 포함하고,
측정한 글자 폭에 1%의 여유를 둡니다. 출처의 병합 셀과 캡션은 열 너비 계산에서
제외합니다. 한글 전용 HFT 글꼴은 지원하지 않습니다. Windows가 요청한 글꼴 대신
다른 글꼴을 선택하면 오류이므로, 해당 글꼴을 설치하거나 샘플의 글꼴을 바꾸십시오.

각 열에는 템플릿의 단어 나눔 설정을 지킬 최소 폭과 한 줄 내용을 담을 선호 폭을
계산합니다. 전체 폭 안에서 최소 폭을 확보한 뒤, 내용 길이에 따라 남은 공간을
배분합니다. 짧은 번호 열은 좁게, 긴 설명 열은 넓게 만들며 원칙적으로 균등 분배하지
않습니다. 각주·상호참조는 실제 번호 필드로 바뀌므로 그 표시를 위한 공간을 예상해 확보합니다.

최소 폭의 합이 `table.width-mm`보다 크면 오류입니다. 이 경우 전체 폭을 늘리거나,
셀 여백·글자 크기를 줄이거나, 원형 문단의 단어 나눔 설정을 조정할 수 있습니다.
한글에서 실제 배치되는 행 높이는 내용에 따라 늘어납니다. Windows 측정과 한글
조판의 차이가 있으므로 대표 출력의 줄바꿈·잘림·페이지 배치는 직접 확인해야 합니다.

전체 폭은 표가 들어갈 구역의 본문 폭 또는 현재 단의 폭을 넘을 수 없습니다.
단이 여러 개이면 동일한 폭의 단만 지원하며, 서로 다른 폭의 단 구성은 명시적으로
거부합니다. 각 열 너비의 합은 지정한 전체 폭과 일치하도록 정수 HWPUNIT로 맞춥니다.

## 지원 범위와 검증

머리행 한 개와 표 몸통 한 개만 지원합니다. 셀 병합, 여러 머리행·중간 머리행·
여러 표 몸통·꼬리행, 셀 안의 여러 문단이나 목록·그림·코드 블록 등의 블록 구조는
지원하지 않습니다. Pandoc JSON의 명시적인 숫자 열 너비,
표·행·셀 속성과 표 ID, 표 번호 상호참조도 지원하지 않습니다. 미지원 구조는
내용을 버리지 않고 오류로 알립니다.

Rust는 표의 직사각형 구조와 모든 셀·캡션·출처의 내용 및 누적 자원 한도를 검증합니다.
백엔드는 한글의 표·캡션·자동번호·서식과 주변 구조를 저장·재열기 후 확인합니다.
내용에 따라 바뀌는 생성 표·셀 높이는 구조 손실과 구분하여 처리합니다. 구조 검증은
시각적인 잘림이나 겹침 검사를 대신하지 않습니다. 생성·검증에 실패하면 기존 결과
HWP를 보존합니다.

각 장에 두 표를 반복하는 검증 원고와 예상 IR은
[`examples/all-features-twice/`](../examples/all-features-twice/)에 있습니다.
`Table:`와 `:` 캡션을 모두 표 위에 두고, 출처가 있는 표와 없는 표를 각각 확인합니다.

캡션·출처 생략과 셀 안 각주를 포함한 짧은 검증 원고는
[`examples/tables/tables.md`](../examples/tables/tables.md)입니다.
기존 배포 템플릿에는 새 표 원형을 직접 추가하거나 새 템플릿을 사용하십시오.
프로그램은 사용자 템플릿에 새 원형을 자동으로 삽입하지 않습니다.
