# md2hwp v0.6.0

Markdown 수식을 한글 수식으로 변환하고, 취소선과 위·아래 첨자를 지원합니다. 프로그램 버전은 **0.6.0**, IR과 원고·템플릿 계약은 **0.6**입니다. 수식과 새 글자 서식을 담기 위해 IR을 0.4에서 0.6으로 올렸으며 IR 0.5는 없습니다. 프로그램과 IR은 계속 독립적으로 버전을 관리합니다.

정확히 대응하는 소스는 [v0.6.0 태그의 자동 소스 다운로드](https://github.com/esnahn/md2hwp/archive/refs/tags/v0.6.0.zip)로 제공합니다.

## 수식

- 문장 안 수식은 `$...$`, 별행 수식은 문단 전체를 `$$...$$`로 씁니다. Pandoc의 `tex_math_dollars`로 읽고, 새 `md2hwp-math` 변환기가 TeX를 한글 수식 SCRIPT로 바꿉니다. 지원하는 TeX 범위와 변환 규칙은 [수식 변환 안내](math.md)에 있습니다.
- IR 0.6은 수식을 한글 SCRIPT로만 담습니다(`inline_math`, `display_math`). 글꼴·크기·번호는 IR에 넣지 않습니다.
- 문장 안 수식은 본문·목록 문단과 그 각주 본문에 쓸 수 있습니다. 제목·표 셀·캡션·대체 텍스트·출처·링크 글자의 수식과 목록 항목 안의 별행 수식은 명시적으로 거부합니다. 금액처럼 글자로 쓰는 `$`가 한 문단에 둘 이상이면 `\$`로 적습니다.
- 문장 안 수식은 속한 문단 스타일의 글자 크기를 쓰고 번호가 없습니다. 별행 수식은 템플릿 표본 문단을 따르고, 수식 글자 크기는 `display_math.fontsize-pt`, 번호는 표본의 수식 번호(AUTONUM)를 씁니다.
- **두 백엔드 모두 수식을 생성합니다.** 한글 백엔드는 한글이 조판한 크기를 그대로 씁니다. rhwp 백엔드는 한글 2020 실측에 맞춘 계산기로 수식의 폭·높이·기준선을 추정하며, 어떤 수식도 거부하지 않습니다. 수식 글꼴은 두 백엔드 모두 `HancomEQN`입니다.

```markdown
피타고라스 정리는 $a^2+b^2=c^2$이다.

$$
\int_0^1 x^2\,dx = \frac{1}{3}
$$
```

설계와 한글 실측 근거는 [수식의 IR 표현](math/ir-design.md)에 있습니다.

## 취소선과 위·아래 첨자

- `~~취소선~~`은 한글 취소선이 됩니다(#9). Pandoc의 `strikeout` 확장으로 읽으며, `1~2`처럼 물결표 하나는 그대로 글자로 남습니다.
- 위·아래 첨자는 HTML 태그 `m<sup>2</sup>`, `H<sub>2</sub>O`로 쓰며 한글의 위 첨자·아래 첨자가 됩니다(#10). 태그는 대소문자를 가리지 않지만 속성은 쓸 수 없고, 같은 강조·링크 범위 안에서 열고 닫아야 합니다. Pandoc의 `^위^`·`~아래~` 표기는 범위 표기 `1~2`와 헷갈리므로 켜지 않았습니다. 그 밖의 HTML은 계속 오류입니다.
- IR 0.6에 `strikeout`, `superscript`, `subscript`가 추가되었습니다. 굵게·기울임과 같은 곳(본문, 제목, 목록, 각주, 표 셀, 캡션, 출처)에 쓸 수 있습니다. 위·아래 첨자를 서로 겹치거나 그 안에 수식을 넣는 것은 거부합니다.
- 두 백엔드 모두 템플릿 글자 모양에 한글 자체의 취소선·위 첨자·아래 첨자 명령과 같은 값을 더합니다. 취소선은 실선·검은색이며, 템플릿 글자 모양에 이미 취소선이 있으면 그 모양과 색을 유지합니다. 표 열 폭은 위·아래 첨자를 한글처럼 글자 크기의 64%로 측정합니다.
- 템플릿에 새 선언은 필요하지 않습니다.
## 기존 IR·템플릿

- 입력 IR과 템플릿의 `ir-version`은 프로그램 IR과 정확히 일치해야 합니다. 이전 IR 0.4 파일은 원고에서 다시 생성하십시오.
- 기존 사용자 템플릿은 `{{md2hwp:ir-version:0.6}}`과 별행 수식 선언(`display_math.fontsize-pt`, `begin:display_math`·`end:display_math`와 `slot:display_math` 표본)을 직접 반영하거나 `init-template`으로 새로 만들어야 합니다. 선언 형식은 [템플릿 안내](templates.md)에 있습니다. 동봉한 기본 템플릿 `template.hwp`에는 수식 스타일과 선언이 들어 있습니다.

## 새 실행 파일: hwpeqrecalc.exe

한글은 파일을 열 때 저장된 수식 크기를 그대로 씁니다. `hwpeqrecalc.exe`는 HWP·HWPX 문서를 한글로 열어 모든 수식을 다시 조판하고 별도 파일로 저장합니다. rhwp 결과를 한글이 만든 크기로 바꿀 때 씁니다. 원본은 바꾸지 않습니다. 저장·재열기 비교에서 수식 크기와 다시 계산된 표 높이, 한글이 다시 인코딩한 그림 외의 변경이 있으면 `hwpeqrecalc: warning:`으로 처음 다른 위치를 알리고 출력은 그대로 저장합니다. 수식 수·스크립트·글자 크기·글꼴이 바뀌거나 저장에 실패하면 오류로 멈추고 기존 출력을 그대로 둡니다.

rhwp 백엔드는 PNG·JPG·EMF 그림의 자르기 크기를 한글이 저장하는 값과 같은 방식으로 기록합니다. 이전에는 한글이 문서를 다시 조판할 때 rhwp가 만든 그림의 이 값을 바꿨습니다.

```powershell
.\hwpeqrecalc.exe 결과.hwp
.\hwpeqrecalc.exe 결과.hwp --output 결과.hwpx
```

[동작과 검증 범위](hwpeqrecalc.md)를 참고하십시오.

## 실행 중인 한글과 함께 실행

한글 백엔드, `hwp2pdf.exe`, `hwpeqrecalc.exe`는 이제 실행 중인 한글을 닫지 않아도 됩니다. 각 실행은 자기 한글 프로세스를 따로 띄워 그것만 닫으며, 사용자가 열어 둔 한글 창과 문서는 건드리지 않습니다. 템플릿이나 원본이 사용자 한글에 열려 있어도 저장된 파일을 읽으며, 저장하지 않은 변경은 반영되지 않습니다.

## 실행 환경과 배포 구성

일반 Debug·Release 빌드와 실행용 ZIP은 `md2hwp.exe`, `md2hwp-rhwp.exe`, `md2hwp-hancom.exe`, `hwp2pdf.exe`, `hwpeqrecalc.exe` 다섯 실행 파일을 포함합니다.

rhwp를 통한 HWP 생성(수식 포함)·템플릿 검사·템플릿 생성에는 한글·.NET·보안 모듈이 필요하지 않습니다. Markdown 처리에는 별도로 설치한 Pandoc이 필요하며, 표 열 폭과 목록 표식 실측에는 Windows에 설치된 TTF/OTF 글꼴이 필요합니다.

HWPX와 한글 백엔드, `hwp2pdf.exe`, `hwpeqrecalc.exe`에는 한글, .NET 10 x64 런타임, 등록된 한글 보안 모듈이 필요합니다. `hwp2pdf.exe`와 `hwpeqrecalc.exe`는 필요한 관리 어셈블리를 자체 EXE에 포함합니다. [설치와 실행](usage.md)을 참고하십시오.

ZIP에는 기본 HWP 템플릿, README, 원고 작성 안내 두 문서, PowerShell 자동완성과 `LICENSE`, `THIRD-PARTY-NOTICES.txt`, `licenses/`도 포함합니다. 프로젝트 코드는 AGPL-3.0-only이며 제3자 자료는 각 원저작자의 조건을 따릅니다. 발행 시 실행용 ZIP만 릴리스에 첨부하고 SHA-256을 릴리스 본문에 기록하며, 정확히 대응하는 v0.6.0 태그의 GitHub 자동 소스 다운로드 링크를 같은 페이지에 제공합니다.

## 지원 범위와 알려진 제한

- rhwp의 수식 크기는 추정값입니다. 실측 자료에서 높이 오차 90%값은 맞춤 자료 4, 툴바 수식 50, 크기별 자료 15~28 HWPUNIT(75 = 1픽셀)입니다. 110쪽·수식 149개 시험 원고에서 쪽 나눔은 한글 백엔드와 같았지만, 별행 수식 폭이 최대 4.5픽셀 달라 가운데 정렬 위치가 조금 다릅니다. 폭을 작게 추정하면 수식이 뒤 글자에 붙을 수 있습니다. 한글과 같은 크기가 필요하면 `hwpeqrecalc.exe`를 쓰십시오.
- 목록 항목 안의 별행 수식, 그리고 제목·표 셀·캡션·출처의 수식은 지원하지 않습니다.
- 변환기가 지원하지 않는 TeX 명령(예: `\mid`)은 원고 위치와 함께 오류로 보고합니다.
- `hwpeqrecalc.exe`로 HWP→HWPX 변환을 하면 한글의 HWPX 저장이 수식 밖의 내용을 바꿀 수 있습니다(예: 한글 기본 문서의 개요 수준 8 문단 모양). 이때는 경고가 나오며 출력은 저장됩니다. 이런 손실을 피하려면 원본과 같은 형식으로 출력하십시오.
- v0.5.0의 알려진 제한은 그대로입니다. 긴 고정 크기 코드 박스와 추적 템플릿의 TreatAsChar 표는 잘릴 수 있고, rhwp는 HWPX를 지원하지 않으며, 한글 백엔드 `init-template`이 만든 새 HWPX 템플릿은 원고 변환의 HWPX→HWP 정규화 검사에서 실패할 수 있습니다. 이번 릴리스에서 이 문제들을 다시 시험하거나 고치지 않았습니다. [v0.5.0 릴리스 노트](release-v0.5.0.md)를 참고하십시오.
- 저장·재열기 구조 검증만으로 수식의 넘침·겹침이나 표시 번호를 판정할 수 없으므로 생성된 문서의 배치를 확인하십시오.

## v0.6.0 검증 — 2026-11-10

- Rust 전체 테스트 **625개**, fmt, Clippy `-D warnings`, C# 계약 검사, 제3자 고지 **308개 잠금 패키지** 검사와 Release 패키지 빌드 통과.
- 실행용 ZIP을 새 폴더에 풀어 확인: 다섯 EXE의 버전 0.6.0(한글 백엔드는 `md2hwp --version --worker`로 확인), README의 v0.6.0 대응 소스 링크, 동봉 `AGENTS.md`가 원고 작성 지침인지, 기본 템플릿의 IR 0.6 검사.
- ZIP에서 rhwp 기본 경로로 취소선·위아래 첨자 원고와 수식 원고의 엄격 검사·변환, 110쪽·수식 149개 원고 변환(6초)을 확인했습니다.
- 같은 ZIP에서 한글 2020으로 취소선·위아래 첨자 원고의 HWP·HWPX 생성, `hwp2pdf`, `hwpeqrecalc`(수식 6개, 그림이 있는 큰 원고 149개)가 성공했습니다. `hwpeqrecalc`는 두 원고 모두 경고 없이 저장했습니다. 이번 시험 때는 다른 한글 창이 열려 있지 않았습니다. 실행 중인 한글과 함께 실행하는 동작은 같은 날 앞선 빌드와 [hwpeqrecalc 실측](hwpeqrecalc.md)에서 확인했습니다.
- 취소선·위아래 첨자는 본문·제목·목록·각주·표 셀·표 캡션·출처를 담은 원고로 두 백엔드 결과의 쪽 이미지를 한글에서 직접 만들어 확인했습니다. 두 결과는 픽셀 단위로 같았고, 표가 있는 한글 백엔드 결과도 쪽 이미지를 정상적으로 만듭니다. 수식 배치의 쪽 이미지는 같은 코드로 개발 중에 확인했으며([수식의 IR 표현](math/ir-design.md), [hwpeqrecalc](hwpeqrecalc.md)) 이번 ZIP 시험에서 다시 확인하지 않았습니다.
- 한글 백엔드 실행 파일 `md2hwp-hancom.exe`는 v0.5.0과 같이 .NET을 `DOTNET_ROOT`로만 찾습니다. `md2hwp.exe`를 거쳐 실행하면 자동으로 설정되며, 직접 실행할 때는 `DOTNET_ROOT`를 지정해야 합니다.
