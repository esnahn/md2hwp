# HWP2PDF 그림 품질·해상도 검증 — 2026-10-10

한글 2020 `11.0.0.9136`, Windows x64 대화형 Session 1에서 현재 Release
`hwp2pdf.exe`로 일반·초고해상도 6건과 DPI 경계 18건을 시험했습니다.
이 문서는 시험 조건과 실측 결과를 Git에 기록합니다. 시험 입력·생성 PDF·페이지 이미지·
실행 로그는 로컬 조사 자료이며 Git에 포함되지 않습니다.

## 공통 조건

- 출력은 `PrintToPDFEx`, `GraphicQuality=100`, `Device=5`, `Range=6`, 100% 배율입니다.
- 물리 삽입 크기는 모두 **142×79.875mm**입니다. DPI 경계 시험은 이 크기에서의 **입력 픽셀 밀도**를 바꿨으며 출력 액션 해상도 옵션은 바꾸지 않았습니다.
- 같은 8192×4608 시험 도안에서 PNG를 LANCZOS 축소했습니다. JPG는 각 PNG를 품질 100·4:4:4로 저장했고 모든 양자화 항목은 1입니다. 품질 100 JPG도 원본 PNG 픽셀과 같다는 뜻은 아닙니다.
- EMF+ Only에는 각 PNG와 같은 벡터 타원·미세선·문자를 넣었습니다. 입력 DPI는 **EMF 내부 비트맵** 기준이며 벡터 자체의 해상도를 뜻하지 않습니다.
- 그림 축소·잘라낸 부분 삭제·형식 변경을 HWP 생성 동안만 끄고 원래 설정을 복원했습니다. 24개 HWP 모두 입력 그림과 내장 바이트가 같았습니다.
- PDF 그림의 실제 배치 크기는 **141.9098×79.7959mm**입니다. 좌표 환산 차이를 보정하지 않고 실제 배치 크기로 유효 DPI를 계산했습니다.

## 권장 입력

PNG·JPG는 **최종 삽입 크기를 기준으로 500dpi로 저장**하는 것을 권장합니다.
142×79.875mm라면 약 **2795×1572픽셀**입니다. 현재 출력 설정에서 추가 축소를
줄이기 위한 기준이며 원본 픽셀 일치를 보장하지 않습니다.
계산식과 준비 방법은 [사용 안내](hwp2pdf.md#입력-그림-권장-해상도)에 있습니다.

## 일반·초고해상도 비교

일반 입력은 2560×1440, 초고해상도 입력은 8192×4608입니다.

| 입력 | PDF 그림 픽셀 | 실제 DPI (가로/세로) | PDF 용량 | 그림 압축 | 결과 |
| --- | --- | --- | --- | --- | --- |
| 일반 JPG | 2560×1440 | 458.2/458.4 | 829.2 KiB | Flate | 픽셀 크기 유지, 원본 픽셀 불일치 |
| 일반 PNG | 2560×1440 | 458.2/458.4 | 361.2 KiB | Flate | 픽셀 크기 유지, 원본 픽셀 불일치 |
| 일반 EMF+ Only | 3364×1887 | 602.1/600.7 | 846.6 KiB | Flate | 벡터·비트맵 전체 래스터화 |
| 초고해상도 JPG | 2795×1572 | 500.3/500.4 | 1385.2 KiB | Flate | 8192×4608에서 축소 |
| 초고해상도 PNG | 2795×1572 | 500.3/500.4 | 493.8 KiB | Flate | 8192×4608에서 축소 |
| 초고해상도 EMF+ Only | 3364×1887 | 602.1/600.7 | 532.7 KiB | Flate | 벡터·비트맵 전체 래스터화 |

전체 그림 스트림에서 JPEG용 DCTDecode는 없었습니다. PDF의 그림에는 JPEG 품질 숫자를 붙일 수 없습니다.
JPG 입력도 PDF에서는 RGB 래스터로 풀어서 Flate 압축했습니다. **Flate 무손실 압축은 압축 전 그림 변환·색상 처리·축소가 없다는 뜻이 아닙니다.**

JPG·PNG는 490·500dpi 입력의 픽셀 크기를 유지했고, 510·590·600·610dpi 입력은 모두 같은 약 500dpi 격자로 축소했습니다.
이번 표본으로 약 500dpi 출력 상한을 재확인했지만, 정확한 축소 시작 경계는 500과 510 사이를 더 촘촘히 시험해야 결정할 수 있습니다.
EMF는 입력 비트맵 밀도와 무관하게 같은 약 600dpi 격자로 전체 래스터화했습니다. 610dpi를 넣어도 출력 격자는 커지지 않았고,
490dpi 비트맵을 넣은 EMF의 출력 격자가 커진 것이 원본에 없던 세부 정보를 복원한다는 뜻은 아닙니다.
이 관찰은 위 한글 버전·액션·설정·삽입 크기의 시험 결과입니다. 모든 버전·개체·출력 방법의 상한으로 일반화하지 않습니다.

## 픽셀 비교 방법

픽셀 오차는 RGB 채널 절대 차이의 평균이며 범위는 0–255입니다.
해상도가 유지된 PNG·JPG는 원본 디코딩과 비교하고, 축소된 입력은 출력 격자로
LANCZOS 축소한 기준과 비교했습니다. 후자의 수치에는 보간 방식 차이와 색상 처리 등이 함께 들어갑니다.
원본 JPG 자체의 PNG 대비 손실은 원본 JPG 디코딩과의 오차에 포함하지 않습니다.

EMF는 PDF와 같은 격자로 직접 Windows GDI+ 렌더링한 결과와 비교했습니다.
PDF의 명시적 1비트 마스크를 흰 페이지에 합성한 뒤 계산했습니다.
내용 정합을 위한 이동·확대·축소를 하지 않아 위치·배율·보간·글자 가장자리 차이가 남습니다.
빽빽한 줄무늬는 작은 위치 차이에도 큰 오차를 만들므로 이 수치를 JPEG 손실이나
형식별 화질 순위로 해석하지 않습니다. Windows 구현을 공유할 수 있으므로 독립 엔진 검증을 주장하지 않습니다.

## 페이지·문자·원본 검증

24개 모두 정상 종료했고 각각 한 페이지입니다. strict PDF 파서로 읽고
전체 페이지를 Poppler 144dpi로 렌더링하여 검토했으며 글자·미세선·벡터 확대 비교도 확인했습니다.
그림 누락이나 겹침은 보이지 않았습니다. 미세선의 회색화·모아레와
EMF 선·문자의 위치·가장자리 차이는 관찰됐습니다.

본문 검색 문자열은 모두 추출됐습니다. EMF 안의 `VECTOR 한글 0123`은 표시되지만
PDF 문자로 추출되지 않았으므로 검색 가능한 벡터 문자로 유지됐다는 뜻은 아닙니다.
입력 HWP·그림의 SHA-256은 출력 전후 동일했고 그림 저장 설정도 복원됐습니다.
시험 후 한글 프로세스와 PDF 임시 폴더가 남지 않았습니다.

프로그램 코드는 이 조사에서 변경하지 않았습니다. PDF 완료 표식 검사와 별도로
수행한 실제 한글·시각 검증 결과이며 다른 한글 버전이나 출력 방법까지 보장하지 않습니다.
