# rhwp 코드 박스 생성 시험 — 2026-10-21

IR 0.4와 고정 rhwp 커밋을 유지했다. rhwp 생성은 한글 COM·.NET을 사용하지 않으며,
독립 재열기·페이지 비교에는 한글 2020 11.0.0.9136을 사용했다.
기본 백엔드와 릴리스 구성은 변경하지 않았다.

## 지원 범위

- `begin:code/end:code`의 한 셀짜리 native 표와 자체 앵커 서식을 복제한다.
  표 폭·여백·테두리·캡션 옵션을 템플릿에서 가져온다.
- 각 원고 줄을 `code.content` 샘플의 별도 문단으로 만든다. 공백·탭·앞뒤와
  중간 빈 줄, 태그처럼 생긴 리터럴을 보존한다.
- `code.title` 슬롯이 있을 때만 첫 줄의 정확한 `제목:`을 처리한다.
  접두어와 그 뒤 ASCII 공백 하나를 제거하고, 제목 바로 뒤의 빈 줄들을 생략한다.
  제목 슬롯이 없거나 첫 줄이 아니면 원문을 그대로 출력한다.
- 출처 문단마다 native 캡션의 샘플 전체를 복제한다. 접두어·내용의 서식을 별도로
  유지하며 강조·기울임·링크 표시 문구를 지원한다. 출처가 없으면 캡션을 생략한다.
  각주·상호참조는 rhwp의 기존 미지원 범위다.
- 원형 앞뒤의 빈 문단 0–63개를 위치별로 복제한다. 잘못된 슬롯이나 구조는
  원고에서 사용하지 않더라도 거부한다. 셀·캡션의 native 문단 수 상한을 검사한다.

개체 식별자는 새로 할당한다. 코드 표의 ZOrder는 원본 전체의 최대값 뒤에서
순서대로 할당하며 raw payload와 유효한 provenance seal을 함께 갱신한다.
원래 정적 개체의 순서는 수정하지 않는다. 한글 백엔드는 native 삽입에 따라
본문 개체를 바탕쪽 개체보다 먼저 배정하므로 전체 순서값은 두 백엔드가 다르다.
겹치는 정적 도형이 있는 사용자 템플릿까지 동등성을 보장하지 않는다.

## 빈 줄의 저장·재열기 검사

첫 구현에서 빈 셀 문단의 줄 정보는 생성 시 0개, rhwp 재열기 후 1개로 달랐다.
고정 upstream reader가 빈 native 셀 문단의 배치 정보를 파생하는 규칙을 확인했다.
입력 템플릿의 글자 크기·문단 간격·셀 폭·여백으로 해당 기대값을 독립적으로
계산한다. 빈 문단도 슬롯 첫 글자의 서식을 사용한다.

저장된 줄 구분의 dirty 상태는 유지하여 이 기대값을 실제 조판 캐시로 저장하지 않는다.
출력 파일이나 재열기 결과에서 기대 문서를 역으로 만들지 않았고, 최종 모델 비교도
완화하지 않았다. 혼합 글자 서식, 첫·중간·연속·마지막 빈 줄, 네 가지 줄 간격,
너비 계산의 부동소수점 경계에 대해 실제 export/reparse 회귀 테스트를 넣었다.

긴 한 줄, 공백·탭·빈 줄·리터럴, 박스 사이의 번호 목록을 포함한다.

```powershell
pwsh -NoProfile -File tools/development/build.ps1 -Configuration Debug -Rhwp
.\target\debug\md2hwp.exe md2ir tests\fixtures\rhwp-code.md --output artifacts\rhwp-code\source.ir.json
.\target\debug\md2hwp-rhwp.exe artifacts\rhwp-code\source.ir.json artifacts\rhwp-code\rhwp.hwp --template templates\template.hwp
.\target\debug\md2hwp-backend.exe ir2hwp --ir artifacts\rhwp-code\source.ir.json --output artifacts\rhwp-code\hancom.hwp --template templates\template.hwp
```

## 긴 박스의 잘림 — 미해결

별도 120줄 박스를 생성했다. 두 백엔드 결과는 각각 3쪽이고 페이지 픽셀도 같지만,
본문 박스가 페이지 아래로 잘려 뒤쪽 줄과 출처가 보이지 않았다. 다음 쪽에는
박스 뒤의 일반 본문만 나온다. 원문 내용은 구조에 남아 있어 저장·재열기 검사만으로
이 잘림을 판정할 수 없다.

현재 `TreatAsChar=true` 박스의 동작이며 기존 한글 백엔드에서도 재현된다.
여러 쪽에 걸친 박스의 안전한 분할을 지원한다고 보고하지 않는다. 템플릿의
글자처럼 취급 설정이나 문서 구조를 자동으로 바꾸지 않았다.
