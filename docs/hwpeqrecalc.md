# 수식 크기 다시 계산 (hwpeqrecalc)

`hwpeqrecalc.exe`는 HWP·HWPX 문서를 한글로 열어 모든 수식을 한글이 다시 조판하게
하고 별도 파일로 저장합니다.

한글은 파일을 열 때 수식의 저장된 폭·높이·기준선을 그대로 씁니다. 그래서 rhwp
백엔드처럼 한글 없이 수식 크기를 추정해 저장한 문서는 한글이 직접 만든 문서와
줄·쪽 나눔이 조금 다를 수 있습니다. 이 도구는 그 크기를 한글의 값으로 바꿉니다.

## 실행

```powershell
.\hwpeqrecalc.exe 결과.hwp
.\hwpeqrecalc.exe 결과.hwp 다시계산.hwp
.\hwpeqrecalc.exe 결과.hwp --output 결과.hwpx
.\hwpeqrecalc.exe --input 결과.hwpx --output 결과.hwpx.recalc.hwpx
.\hwpeqrecalc.exe --version
.\hwpeqrecalc.exe --help
```

- 기본 출력은 원본 옆의 `결과.recalc.hwp`(HWPX 입력이면 `결과.recalc.hwpx`)입니다.
- 출력 형식은 출력 확장자(`.hwp`·`.hwpx`)를 따릅니다.
- 원본은 바꾸지 않으며, 출력이 원본과 같은 경로이면 거부합니다.
- 실행이 끝나면 수식 수, 크기가 바뀐 수식 수, 다시 조판으로 갱신된 표 높이 수,
  한글이 저장하며 다시 인코딩한 그림 수를 표시합니다. 수식 외 변경이 있으면 그 앞에
  경고를 표시합니다(아래 검증 범위).

`hwp2pdf.exe`와 같이 한글, .NET 10 x64 런타임, 등록된 한글 보안 모듈이 필요하며
실행 중인 한글을 먼저 닫아야 합니다. 템플릿·Pandoc·별도 백엔드 EXE는 필요하지
않습니다.

## 동작

1. 숨긴 한글 창으로 원본을 엽니다.
2. 문서의 모든 수식 컨트롤(본문, 표 셀, 각주, 글상자, 머리말 포함)에 대해 그
   수식의 현재 글꼴(`EqFontName`)을 다시 설정합니다. 값을 바꾸지 않아도 속성을
   설정하면 한글이 그 수식을 다시 조판합니다. 수식 스크립트·글자 크기·글꼴은
   그대로입니다.
3. 임시 파일로 저장하고 다시 열어 확인한 뒤, 원본이 실행 중에 바뀌지 않았으면
   출력으로 옮깁니다. 오류로 실패하면 기존 출력을 그대로 둡니다.

## 검증 범위

- 수식 컨트롤 순서와 HWPML의 EQUATION 순서가 같은지 스크립트로 확인합니다.
- 다시 조판 전후에 수식 수·스크립트·글자 크기·글꼴이 같아야 합니다.
- HWPML 전체를 비교해 수식 폭·높이·기준선과 아래 두 가지 외의 변경이 있으면
  `hwpeqrecalc: warning:`으로 처음 다른 위치를 알리고, 출력은 그대로 저장합니다.
  저장·재열기와 형식 변환(HWP↔HWPX)에서 생긴 변경도 같습니다. 경고가 나오면
  결과를 확인하십시오.
  - 표·셀 높이: 다시 조판할 때 한글이 내용에 맞게 다시 계산합니다. rhwp가 만든
    표의 저장 높이는 한글 값과 다를 수 있습니다.
  - 그림 데이터: 한글은 저장할 때 그림을 다시 인코딩할 수 있습니다. 그림 수와
    참조는 비교하지만 인코딩된 바이트는 비교하지 않습니다.
- 수식 수·순서·스크립트·글자 크기·글꼴이 바뀌거나, 저장·재열기 뒤 수식 크기가
  달라지거나, 저장에 실패하거나, 실행 중 원본이 바뀌면 여전히 오류로 멈추고 기존
  출력을 그대로 둡니다.
- 저장·재열기 비교는 수식 크기까지 포함합니다. HWPX는 기존 HWPX 검증과
  같이 변환 행렬 정밀도와 그림 식별자를 정규화하고, 스크립트가 없는 문서의 기본
  스크립트 머리말을 무시합니다.
- 구조 비교는 화면 배치를 보장하지 않습니다. 쪽 이미지로 확인하십시오.

## 실측 (2026-11-10)

환경: `DESKTOP-BRTN48S\MOLIT`, 대화형 세션 1, 한글 11.0.0.9166, `HWPFrame.HwpObject`.
실행 전 다른 한글 프로세스가 없었고, 매 실행 후 한글이 정상 종료됐습니다.

- 수식 6개 시험 원고의 rhwp 결과: HWP→HWP, HWP→HWPX, HWPX→HWPX 모두 성공. 이미
  다시 계산한 HWPX를 다시 넣으면 바뀐 수식이 0개였습니다. 원본은 바뀌지 않았습니다.
- `examples/korean-lorem/large-5x.md`에 수식 149개를 넣은 원고의 rhwp 결과(110쪽):
  37초, 수식 123개 크기 변경, 표 높이 53개 갱신, 그림 1개 재인코딩. 결과의 수식
  149개가 한글 백엔드 결과와 폭·높이·기준선까지 모두 같았고, 72dpi 쪽 이미지
  110쪽이 픽셀 단위로 모두 같았습니다.
- 본문·표 셀·각주·글상자·머리말에 수식을 하나씩 둔 한글 작성 문서: HWP→HWP는
  수식 5개를 모두 찾았고 바뀐 크기가 없었습니다(한글이 만든 크기이므로).
- 같은 문서의 HWP→HWPX에서는 한글의 HWPX 저장이 기본 문단 모양 하나의
  개요 수준 8을 "없음"으로 바꿨습니다. 수식과 무관한 형식 변환 손실입니다.
  당시에는 거부했고, 지금은 경고만 하고 저장합니다. 이런 손실을 피하려면 원본과 같은
  형식으로 출력하십시오.
