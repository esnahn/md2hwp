# SVG 그림

독립 그림 문단에서 `.svg` 파일을 쓸 수 있습니다. 확장자는 대소문자를 구분하지 않습니다.

```markdown
![그림 설명](diagram.svg){#diagram}
```

한글은 SVG를 직접 받지 않으므로 `md2hwp`가 IR을 만들 때(`md2ir` 단계) SVG를 EMF·PNG·JPG로 바꿉니다.
IR에는 바뀐 파일의 경로만 들어가고, 백엔드는 기존 EMF·PNG·JPG 그림과 똑같이 처리합니다.
IR·템플릿 선언은 바뀌지 않으며 캡션·번호·출처·상호참조도 다른 그림과 같습니다.

## 변환 방식 고르기

`--svg <형식>`으로 고릅니다. 기본 명령과 `md2ir`에서 쓸 수 있습니다.

```powershell
.\md2hwp.exe 원고.md --svg png
.\md2hwp.exe md2ir 원고.md --svg jpg
```

| 값 | 결과 |
| --- | --- |
| `auto` (기본) | 벡터를 유지하는 EMF+ Dual. EMF로 표현할 수 없으면 PNG로 바꿉니다. EMF가 5 MiB를 넘으면 PNG도 만들어 더 작은 쪽을 씁니다. PNG로 바꾼 이유는 표준 오류에 알립니다. |
| `emf` | 크기와 무관하게 항상 EMF를 씁니다. EMF로 표현할 수 없는 SVG를 만나면 이유를 알리고 변환을 실패시킵니다. PNG로 바꾸지 않습니다. |
| `png` | 항상 PNG. 배경은 투명합니다. |
| `jpg` | 항상 JPG(품질 92). 투명한 곳은 흰색이 됩니다. |

원고의 모든 SVG에 같은 방식을 적용합니다.

## 변환 파일

변환 결과는 SVG 옆에 원래 이름에 확장자를 덧붙여 씁니다.
`img/diagram.svg`는 `img/diagram.svg.emf`, `img/diagram.svg.png`, `img/diagram.svg.jpg` 중 하나가 되고 IR 경로도 그 이름입니다.

- 변환할 때마다 다시 만들며, 내용이 같으면 파일을 다시 쓰지 않습니다.
- 생성 파일에는 표식(EMF 헤더 설명 `md2hwp`, PNG `tEXt` 청크 `Software: md2hwp-svg`, JPG 주석 `md2hwp-svg`)을 넣습니다.
  같은 이름의 파일이 이미 있고 이 표식이 없으면 덮어쓰지 않고 오류를 냅니다.
- 형식이 달라지면 이전에 생성한 다른 형식 파일은 지웁니다. 표식이 없는 파일은 지우지 않고 오류를 냅니다.
- `md2hwp validate`는 변환이 되는지만 확인하고 파일을 쓰지 않습니다.
- 직접 작성한 IR이나 `ir2hwp`에 `.svg` 경로를 넣으면 백엔드가 거부합니다. 변환은 `md2ir`만 합니다.

## EMF+ Dual

EMF 파일은 같은 그림을 두 번 담습니다. EMF+ 레코드는 한글·Windows GDI+가 쓰고,
GDI 레코드는 EMF+를 모르는 프로그램(rhwp 뷰어 등)이 씁니다.

| | EMF+ 쪽 | GDI 쪽 |
| --- | --- | --- |
| 가장자리 | 안티앨리어싱 | 계단 모양 |
| 좌표 | 실수 | 1/64 픽셀 정수 |
| 투명도(`fill-opacity`, `stroke-opacity`) | 그대로 | 불투명하게 그림 |

EMF로 바뀌는 SVG 기능은 다음과 같습니다.

- 도형·경로의 단색 채움(`nonzero`, `evenodd`)과 단색 선, 채움·선 투명도
- 도형 하나에 붙은 `opacity`: 색의 투명도로 바꿉니다. 채움과 선이 함께 있으면 선이 덮는 곳에는 채움을 그리지 않아
  SVG와 같은 결과를 냅니다.
- 선 굵기·끝 모양·이음 모양·점선: 선을 윤곽 도형으로 바꿔 채우므로 변환(회전·비균등 확대)에도 모양이 유지되고,
  반투명 선이 스스로 겹쳐도 진해지지 않습니다.
- 같은 색으로 채운 도형 묶음의 `opacity`(반투명 글자 등): 합친 모양을 그 색으로 한 번 칠합니다.
- 패턴 채움과 선(빗금 등): 도형을 클립으로 걸고 패턴의 타일 내용을 도형을 덮는 만큼 반복해 그립니다.
  타일 내용도 위 범위 안이어야 하고, 한 도형에 4096타일까지 그립니다.
- PNG·JPEG 내장 이미지(data URL): 아래 "래스터 이미지" 참고
- 그룹 변환, `viewBox`
- 텍스트: 설치된 글꼴로 윤곽선을 만들어 넣습니다. 한글에서 글자로 편집할 수는 없습니다.
- 도형 하나로 된 `clip-path`

다음 중 하나라도 있으면 EMF로 표현할 수 없습니다. `--svg auto`는 PNG로 바꾸고 `--svg emf`는 실패합니다.

- 색이 다르거나 선이 있는 도형 여러 개를 묶은 그룹의 투명도(`opacity`), 반투명 선과 함께 쓴 도형 `opacity`
- 그라데이션 채움과 선, 반투명 패턴, 4096타일을 넘는 패턴
- 마스크, 필터, 혼합 모드
- GIF·WebP·SVG 형식의 내장 이미지, 그룹 투명도 아래의 이미지
- 도형이 여럿이거나 중첩된 `clip-path`

### 규격 대조 — 2026-11-13

기록기가 쓰는 레코드를 Microsoft 공개 규격 [\[MS-EMFPLUS\]](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-emfplus/)와
[\[MS-EMF\]](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-emf/)의 해당 절과 대조했습니다.

| 레코드 | 규격 절 | 기록 값 | 결과 |
| --- | --- | --- | --- |
| EMF+ 레코드 머리말 | 2.3.3 | `Size`·`DataSize` 모두 4바이트 정렬 | 일치 |
| `EMR_COMMENT_EMFPLUS` | MS-EMF 2.3.3.2 | 종류 `0x46`, `DataSize` = 식별자 4바이트 + EMF+ 레코드, 식별자 `0x2B464D45` | 일치 |
| `EmfPlusHeader` `0x4001` | 2.3.3.3 | 플래그 `0x0001`(Dual), 버전 `0xDBC01002`, 화면 기준 장치, 96dpi. EMF 머리말 바로 다음 레코드에 넣음 | 일치 |
| `EmfPlusSetAntiAliasMode` `0x401E` | 2.3.6.1 | 플래그 `0x0009` = `AntiAlias8x4` + A 비트 | 일치 |
| `EmfPlusSetPageTransform` `0x4030` | 2.3.9 | 플래그 `0x0002` = `UnitTypePixel`, 배율 1.0 | 일치 |
| `EmfPlusSetClipRect` `0x4032` | 2.3.1.4 | 결합 방식 `Replace`, `EmfPlusRectF`(X, Y, Width, Height) | 일치 |
| `EmfPlusObject` `0x4008` | 2.3.5.1 | 플래그 `0x0300` = 경로 개체, ID 0 | 일치 |
| `EmfPlusPath` | 2.2.1.6 | 버전, 점 개수, 플래그, `EmfPlusPointF` 배열, 점 종류 배열, 정렬 패딩 | 일치 (아래 플래그 제외) |
| 점 종류 | 2.1.1.22, 2.1.2.6 | 시작 0, 직선 1, 베지어 3, 닫기 `0x80` | 일치 |
| `EmfPlusFillPath` `0x4014` | 2.3.4.17 | 플래그 `0x8000`(단색), 색은 파랑·초록·빨강·알파 순 | 일치 |
| `EmfPlusSetClipPath` `0x4033` | 2.3.1.3 | 플래그 `0x0100` = `Intersect`, 경로 ID 0 | 일치 |
| `EmfPlusSave`·`EmfPlusRestore` `0x4025`·`0x4026` | 2.3.7.5, 2.3.7.4 | 4바이트 `StackIndex`, 짝을 맞춰 기록 | 일치 |
| `EmfPlusEndOfFile` `0x4002` | 2.3.3.1, 1.3.1 | 데이터 없음. `EMR_EOF` 바로 앞 레코드에 넣음 | 일치 |

규격으로 확인되지 않는 것은 두 가지입니다.

- **경로 플래그 `0x2000`(Winding 채움).** 규격은 경로 플래그에 R·C 비트만 정의하고 나머지는 0으로 둡니다.
  Windows GDI+는 Winding 경로를 기록할 때 이 비트를 쓰고, 재생할 때도 따릅니다. 같은 방향으로 겹친 두 사각형을
  `nonzero`와 `evenodd`로 변환해 GDI+로 그리면 가운데가 각각 채워지고 비는 것을 확인했습니다. 한글 2020도 선 윤곽을
  올바르게 채웁니다. 이 비트를 무시하는 재생기는 `nonzero` 도형과 선 윤곽이 겹치는 곳을 비워 그릴 수 있습니다.
- **Dual의 GDI 쪽.** 규격(1.3.1)은 Dual 파일의 EMF 레코드가 그림 전체를 올바르게 그릴 수 있어야 한다고 합니다.
  투명도는 GDI로 표현할 수 없어 GDI 쪽은 불투명하게 그립니다.

쪽 단위는 규격이 기본값을 정하지 않아 `EmfPlusSetPageTransform`으로 픽셀 단위를 명시합니다.

`EmfPlusSetPixelOffsetMode`(2.3.6.5)는 쓰지 않습니다. `Half`를 넣으면 GDI+가 그림 전체를 0.5픽셀 왼쪽 위로 옮겨 그립니다.
32×32 SVG의 8..24 사각형을 100배로 그려 보면 `Half`에서는 750..2348, 레코드가 없으면 800..2398에 놓입니다.

## EMF로 들어가는 SVG 만들기

벡터로 넣으려면 SVG를 다음 범위 안에서 만드십시오.

- 채움과 선은 단색이나 패턴(빗금)을 씁니다. 그라데이션은 쓰지 않습니다.
- 투명도는 도형 하나하나에 줍니다(`fill-opacity`, `stroke-opacity`, 도형의 `opacity`). 여러 도형을 묶은 그룹에는 주지 않습니다.
- 마스크·필터(그림자, 흐림)·혼합 모드는 쓰지 않습니다.
- 래스터 이미지는 PNG나 JPEG를 data URL로 넣습니다. 이미지 부분은 래스터로 남고 나머지는 벡터입니다.
- `clip-path`는 사각형 등 도형 하나로 만듭니다.
- 글자는 그대로 두어도 되고 윤곽선으로 바꿔도 됩니다. 그대로 둘 때는 변환하는 PC에 그 글꼴이 있어야 합니다.

matplotlib 그래프는 선·점·막대·채움·빗금(`hatch=`)·등고선·눈금·글자·범례·3차원 그림이 이 범위에 들어갑니다. `alpha=`, 범례의 반투명 틀,
반투명 글자도 EMF로 갑니다([갤러리 시험](#matplotlib-갤러리-시험--2026-11-13)). `imshow`, 색상 막대,
`rasterized=True`로 들어간 이미지는 EMF 안에 이미지로 들어가고 축·글자·선은 벡터로 남습니다. 다음은 PNG로 바뀝니다.

- `shading="gouraud"`, 그림자·흐림 효과(`patheffects`의 일부)
- 투명도를 준 빗금

`hist2d`·`pcolormesh`처럼 칸이 촘촘히 맞닿은 그림은 EMF로 들어가지만 칸 사이에 가는 이음선이 보일 수 있습니다.
이런 그림은 `rasterized=True`로 저장하거나 `--svg png`를 쓰는 편이 낫습니다.

```python
fig.savefig("plot.svg")           # 글자는 기본값(윤곽선)으로 저장됩니다.
```

EMF가 되는지 미리 확인하려면 `svg2emf plot.svg`를 실행하십시오. 안 되면 걸린 기능을 알려 줍니다.

## svg2emf

`svg2emf.exe`는 같은 변환기를 쓰는 단독 도구입니다. `md2hwp.exe`는 이 파일을 쓰지 않습니다.

```powershell
.\svg2emf.exe 그림.svg                 # 그림.emf
.\svg2emf.exe 그림.svg 결과.png        # 출력 확장자가 형식을 정합니다
.\svg2emf.exe 그림.svg --output 결과.jpg
```

- `.emf`는 EMF+ Dual, `.png`는 투명 배경 PNG, `.jpg`·`.jpeg`는 흰 배경 JPG입니다.
- `.emf` 출력은 EMF로 표현할 수 없는 그림이면 걸린 기능을 알리고 실패합니다. PNG로 대신 만들지 않습니다.
- 원본은 바꾸지 않습니다. 출력 파일이 이미 있으면 변환에 성공했을 때만 교체합니다.

## 래스터 이미지

SVG 안의 PNG·JPEG 이미지는 EMF에 두 번 들어갑니다.

| | EMF+ 쪽 | GDI 쪽 |
| --- | --- | --- |
| 데이터 | 원본 PNG·JPEG 파일 그대로 | 압축 없는 24비트 비트맵, 긴 변 1024픽셀까지(넘으면 줄임) |
| 투명도 | 그대로 | 반투명 이하(알파 128 미만)는 투명, 나머지는 불투명 |
| 회전·기울임 | 세 점으로 배치 | 월드 변환으로 배치 |
| 보간 | `image-rendering`에 따라 최근접·쌍선형·고품질 쌍삼차 | 색 그대로 늘림 |

- GDI+는 원본 픽셀의 중심을 정수 좌표로 보므로 원본 영역을 (-0.5, -0.5)에서 시작하게 적습니다. 그렇지 않으면
  이미지가 원본 반 픽셀만큼 밀리고 끝이 빕니다.
- 부드러운 보간에서는 가장자리 밖을 반사해 읽도록 이미지 속성(`WrapMode TileFlipXY`)을 붙입니다. 없으면 가장자리가
  투명 쪽으로 번집니다.
- 이미지가 든 EMF는 GDI 쪽 비트맵만큼 커집니다. matplotlib 갤러리의 이미지 그림에서는 그림당 중앙값 0.2 MB, 최대 1.3 MB입니다.

## 큰 EMF와 `auto`

작은 도형이 수만 개인 그림은 EMF가 PNG보다 훨씬 커질 수 있습니다. 도형마다 EMF+ 쪽과 GDI 쪽에 경로를 한 번씩 쓰기 때문입니다.
`--svg auto`는 EMF가 5 MiB를 넘을 때만 PNG를 만들어 크기를 비교하고, PNG가 더 작으면 PNG를 씁니다.
5 MiB 이하의 EMF는 PNG보다 커도 그대로 씁니다.

matplotlib 갤러리에서는 EMF로 변환되는 765개 중 17개가 5 MiB를 넘고, 17개 모두 PNG가 더 작아 PNG로 들어갑니다
(예: 3차원 면 25.7 MiB → 0.7 MiB, `hist2d` 격자 21.2 MiB → 2.3 MiB, 빗금 무늬 모음 9.5 MiB → 1.6 MiB). 2400픽셀 PNG는 갤러리 전체에서 중앙값 0.4 MB,
상위 1% 4.0 MB, 최대 7.7 MB입니다.

## PNG·JPG

resvg로 그립니다. 가로 2400픽셀을 기준으로 하고(원본이 더 크면 원본 크기),
가로·세로 모두 8000픽셀을 넘지 않게 줄입니다.

## 거부하는 SVG

- 해석할 수 없는 SVG, 64 MiB를 넘는 파일, 가로나 세로가 20000픽셀을 넘는 그림
- 다른 파일을 참조하는 `<image>`: 변환 중에 SVG가 가리키는 파일은 읽지 않습니다. data URL로 내장하십시오.
- 글꼴을 찾지 못해 윤곽선으로 바꿀 수 없는 텍스트

## rhwp의 EMF+ 지원 — 2026-11-13

고정 커밋 `1a76570`(0.8.7)에는 EMF+ 재생기가 없고 GDI 레코드만 그립니다. `eb84afc`(0.9.0)에는
제한된 EMF+ 재생기가 있지만 WMF에 내장된 EMF에만 쓰이고, `.emf` 그림은 여전히 GDI 레코드로 그립니다.
그래서 EMF+ Only가 아니라 Dual로 기록합니다. rhwp 백엔드는 EMF 바이트를 그대로 내장하므로 생성에는 영향이 없습니다.

## 검증 — 2026-11-13

[예제](../examples/svg/svg.md)는 EMF로 바뀌는 그림(둥근 사각형, 점선 원, `evenodd` 구멍, 곡선, 회전한 한글 텍스트,
반투명 원과 선, 클리핑)과 PNG로 바뀌는 그림(그라데이션)을 넣습니다.

- 생성한 EMF를 Windows GDI+가 `EmfPlusDual`로 인식하고, 직접 그린 결과가 SVG와 같은 모양인지 눈으로 확인했습니다.
- EMF+ 주석을 뺀 GDI 쪽만 따로 그려, 반투명 원이 불투명한 것 말고는 같은 모양임을 확인했습니다.
- rhwp 백엔드로 HWP를 만들고 저장·재열기 검증을 통과했습니다.
- 그 HWP를 한글 2020 `11.0.0.9136`에서 `hwp2pdf`로 PDF로 바꿔 3쪽을 확인했습니다. EMF는 안티앨리어싱과
  반투명이 살아 있고, 두 형식 모두 캡션·번호·참조와 함께 표시됩니다.

- matplotlib 형식의 그래프 SVG(범례 틀 `opacity` 포함)를 넣은 HWP를 한글 2020에서 PDF로 바꿔 표시를 확인했습니다.
  이 확인은 `EmfPlusSetPixelOffsetMode`를 빼기 전의 EMF로 했습니다.
- 한글 백엔드(`md2hwp-hancom.exe`)로 같은 원고의 HWP와 HWPX가 생성되는 것을 확인했습니다. 표시는 확인하지 않았습니다.

확인하지 않은 것: 한글 백엔드로 만든 결과와 HWPX 출력의 한글 표시, `--svg jpg`·`--svg png` 결과의 한글 표시,
한글 화면·쪽 이미지에서의 픽셀 비교, rhwp 뷰어 등 한글 외 프로그램의 표시, 위 예제에 없는 SVG 기능의 변환 품질.

## matplotlib 갤러리 시험 — 2026-11-13

matplotlib 3.11.2의 예제 갤러리(`galleries/examples`, 507개)를 화면 없이 실행해 남은 그림을 모두
`savefig("….svg")`로 저장하고 `svg2emf`로 변환했습니다. 471개 예제가 실행되어 그림 777개가 나왔습니다
(나머지 36개는 GUI·LaTeX 등 이 환경에 없는 것이 필요하거나 시간 초과).

| 결과 | 그림 수 | 내용 |
| --- | --- | --- |
| EMF로 변환 | 765 | 빗금 그림 14개, 이미지가 든 그림 154개 포함 |
| 반투명 패턴 | 1 | 투명도를 준 빗금 |
| 필터 | 3 | Gouraud 음영 |
| SVG가 잘림 | 7 | matplotlib이 저장 도중 실패한 파일(LaTeX 없음 등). 해석 오류로 거부 |
| 64 MiB 초과 | 1 | 520 MB짜리 SVG |

Gouraud 음영과 반투명 빗금이 없는 그림은 모두 EMF가 되었습니다. 이 수는 `svg2emf`(크기 규칙 없음) 기준이며,
`--svg auto`에서는 5 MiB를 넘는 17개가 PNG로 들어가 748개가 EMF로 남습니다.

변환된 765개는 EMF를 Windows GDI+로 가로 800픽셀로 그려, 같은 SVG의 resvg PNG와 화소 단위로 비교했습니다.
채널 최대 차이의 평균은 중앙값 2.3/255, 90번째 백분위 5.5/255, 최댓값 17.1/255입니다. 차이가 큰 그림을
눈으로 확인하니 가는 선(빗금 포함)과 촘촘한 줄무늬 이미지의 표본화 차이, `hist2d` 격자의 이음선이었고,
빠지거나 어긋난 도형은 없었습니다. 이 비교로 0.5픽셀 어긋남(고치기 전 최댓값 32.1), 이미지의 반 픽셀 밀림과
보간 방식 차이(고치기 전 최댓값 30.1)를 찾아 고쳤습니다.

이 시험은 GDI+ 표시를 기준으로 합니다. 갤러리 그림 전체를 한글에서 열어 보지는 않았습니다.
빗금 10종을 모은 그림(`hatch_style_reference`), 이미지가 든 그래프(`petroff10`), 투명도가 있는 이미지를 곧게·기울여
넣은 시험 그림은 한글 2020에서 PDF로 바꿔 표시를 확인했습니다. EMF+ 주석을 뺀 GDI 쪽만 그려 비트맵·마스크·기울임도 확인했습니다.

## 텍스처 브러시와 이미지 — 2026-11-13

빗금을 EMF+ 텍스처 브러시로 넣는 방법과, SVG 안의 래스터 이미지를 EMF에 넣을 가능성을 한글 2020에서 확인했습니다.
시험 파일은 Windows GDI+로 기록했습니다.

| 시험 | Windows GDI+ | 한글 2020 |
| --- | --- | --- |
| 비트맵 타일 텍스처 브러시 (Dual, Only) | 그림 | 그림 |
| 메타파일(벡터) 타일 텍스처 브러시, 직접 작성 | 채운 도형을 그리지 않음 | 채운 도형을 그리지 않음 |
| PNG 이미지 개체 + `EmfPlusDrawImagePoints` (Dual, Only; 투명도, 기울인 배치) | 그림 | 그림 |

- GDI+는 메타파일로 텍스처 브러시를 만들어도 브러시 안에 비트맵으로 바꿔 저장합니다. 규격에 있는 메타파일 타일은
  GDI+와 한글 모두 그리지 않으므로, 빗금을 벡터로 넣는 데는 텍스처 브러시를 쓰지 않고 반복 그리기를 씁니다.
- 이미지는 PNG 바이트를 그대로 담은 이미지 개체로 기록되고 한글이 투명도까지 그립니다. 변환기는 이 형식으로
  이미지를 넣습니다.
