# md2hwp v0.5.0 — 릴리스 준비

HWP 기본 생성을 rhwp 백엔드로 전환하고, HWPX는 한글 자동화 백엔드로 선택합니다. 프로그램 버전은 **0.5.0**, IR과 원고·템플릿 계약은 **0.4**를 유지합니다. 프로그램과 IR은 독립적으로 버전을 관리하며, 프로그램 버전에 맞춰 IR이나 템플릿의 `ir-version`을 변경하지 않습니다.

이 문서는 발행 준비 중인 변경 사항입니다. v0.5.0 태그·실행용 ZIP·GitHub Release는 아직 발행하지 않았습니다. 최신 공개 배포는 [v0.4.4](https://github.com/esnahn/md2hwp/releases/tag/v0.4.4)입니다.

## 백엔드 선택

- `--worker`를 생략하고 템플릿과 출력이 HWP이면, `md2hwp.exe` 옆의 `md2hwp-rhwp.exe`를 우선합니다. 그 파일이 없을 때만 `md2hwp-hancom.exe`를 선택합니다.
- 템플릿 또는 출력이 HWPX이면 `md2hwp-hancom.exe`만 자동 선택합니다. 확장자 대소문자는 구분하지 않습니다. rhwp는 HWP 전용이며 HWPX를 거부합니다.
- 명시한 `--worker`가 자동 선택보다 우선합니다. 선택한 파일이 없거나 실행·검증에 실패해도 다른 백엔드로 재시도하지 않습니다.
- 같은 규칙을 변환·템플릿 검사·템플릿 생성에 적용합니다. 형식 입력이 없는 `--version`은 rhwp를 먼저 찾습니다. `--dotnet`은 한글 백엔드에만 적용합니다.
- 한글 백엔드 실행 파일 이름은 `md2hwp-hancom.exe`입니다. 기존 `md2hwp-backend.exe`를 명시한 명령·스크립트는 새 이름으로 수정해야 합니다.

```powershell
.\md2hwp.exe 원고.md
.\md2hwp.exe 원고.md --output 결과.hwpx --template 내템플릿.hwp
.\md2hwp.exe 원고.md --worker .\md2hwp-hancom.exe
```

HWPX 템플릿·출력 지원은 v0.4.4부터 제공한 기능입니다. 기본 템플릿·출력은 HWP이며, 별도 `--format` 옵션은 없습니다. 원고 입력은 Markdown 또는 Pandoc JSON이고 HWPX·RST 원고 입력은 지원하지 않습니다. `hwp2pdf.exe`는 HWP 입력만 지원합니다.

## 실행 환경과 배포 구성

일반 Debug·Release 빌드와 실행용 ZIP은 `md2hwp.exe`, `md2hwp-rhwp.exe`, `md2hwp-hancom.exe`, `hwp2pdf.exe` 네 실행 파일을 포함합니다. 빌드의 `-Rhwp` 옵션은 호환용으로 유지합니다.

rhwp를 통한 HWP 생성·템플릿 검사·템플릿 생성에는 한글·.NET·보안 모듈이 필요하지 않습니다. Markdown 처리에는 별도로 설치한 Pandoc이 필요하며, 표 열 폭과 목록 표식 실측에는 Windows에 설치된 TTF/OTF 글꼴이 필요합니다. 지원하지 않는 표식·번호 형식이나 글꼴 대체는 명시적으로 거부합니다.

HWPX와 명시적 한글 백엔드, HWP→PDF에는 한글, .NET 10 x64 런타임, 등록된 한글 보안 모듈이 필요합니다. `hwp2pdf.exe`는 필요한 관리 어셈블리를 자체 EXE에 포함하므로 별도 백엔드 EXE·템플릿·Pandoc이 필요하지 않습니다. [설치와 실행](usage.md)을 참고하십시오.

ZIP에는 기본 HWP 템플릿, README, 원고 작성 안내 두 문서, PowerShell 자동완성과 `LICENSE`, `THIRD-PARTY-NOTICES.txt`, `licenses/`도 포함합니다. 프로젝트 코드는 AGPL-3.0-only이며 제3자 자료는 각 원저작자의 조건을 따릅니다. 발행 시 실행용 ZIP만 릴리스에 첨부하고 SHA-256을 릴리스 본문에 기록하며, 정확히 대응하는 v0.5.0 태그의 GitHub 자동 소스 다운로드 링크를 같은 페이지에 제공합니다.

## 지원 범위와 알려진 제한

rhwp는 일반 문단, 제목 블록과 하위 제목 반복, 메타데이터, 중첩 목록, 코드 박스, PNG/JPEG/EMF 그림, 표, 각주와 번호 상호참조를 지원합니다. [기능 동등성 검토](rhwp-parity-2026-10-23.md)와 [제한 분류](rhwp-limit-classification-2026-10-23.md)는 검증한 범위와 남은 차이를 구분합니다. 임의 템플릿까지 포함한 완전한 동등성을 보장하지 않습니다.

한글의 JPEG 재인코딩에 따른 관찰된 표시 차이는 사용자가 수용했습니다. 이는 다른 이미지 형식·원본 보존·구조·배치 검사를 생략하는 허용이 아닙니다. 긴 고정 크기 코드 박스와 추적 템플릿의 TreatAsChar 표는 잘릴 수 있으며, 저장·재열기 구조 검증만으로 넘침이나 겹침을 판정할 수 없습니다. rhwp의 HWPX 미지원과 지원하지 않는 템플릿 구조 등의 제한도 남아 있습니다.

**새 Hancom HWPX 기본 템플릿:** `init-template 새템플릿.hwpx`와 `validate-template`이 성공해도, 이 새 템플릿으로 원고를 생성할 때 HWPX→HWP 정규화 검사에서 코드·표 원형 높이와 그림 캡션 폭 차이로 실패하는 문제가 재현됐습니다. 원고 합성 전 검사이며 백엔드 자동 선택과 직접 실행 모두에서 발생합니다. 기존 검증 HWPX 템플릿과 추적 HWP 템플릿의 HWPX 출력은 성공했습니다. 구조 검사를 완화하지 않았으며 실패한 결과는 게시되지 않았습니다. [상세 재현 기록](backend-selection-2026-10-23.md#별도-발견-새-hancom-hwpx-기본-템플릿)을 참고하십시오.

## 기존 검증 근거

[2026-10-23 백엔드 선택 검증](backend-selection-2026-10-23.md)은 선택 동작 구현 `c6efe8e`와 문서화 `be52353` 시점의 기록입니다. 당시 프로그램 메타데이터는 0.4.4였으며 이 기록 자체를 v0.5.0 패키지 검증으로 간주하지 않습니다.

기록에는 Rust 291개 테스트·Clippy·fmt·C# 계약 검사, Debug·Release 빌드, 각 구성의 12개 독립 실행 사례, 한글 2020의 HWP/HWPX 경로 검증과 정상 COM 종료가 포함됩니다. PDF 실제 변환·시각 비교를 다시 수행한 기록은 아닙니다.

## v0.5.0 빌드 검증

버전 상향 후 Rust 291개 테스트, Clippy `-D warnings`, fmt, C# 계약 검사와 제3자 고지 검사를 다시 통과했습니다. 외부 의존성 버전은 변경하지 않았고, IR 상수·스키마·템플릿도 0.4를 유지했습니다.
버전 메타데이터와 독립 버전 규칙은 `c6816b2`에 기록했습니다. 정상 Debug·Release 빌드도 통과했습니다.

Release ZIP을 별도 폴더에 풀어 네 EXE의 0.5.0 버전 출력, rhwp 기본 선택, 템플릿 검사·생성, Markdown 변환과 기존 IR 0.4 변환을 확인했습니다. 총 8개 실행 검사를 통과했으며 기본 템플릿·원고 지침·라이선스와 ZIP의 EXE 네 개 구성도 검사했습니다. 증거는 ignored `artifacts/version-0.5.0/`에 보관합니다.

이 버전 상향 단계에서는 한글 COM 변환·픽셀 대조를 새로 수행하지 않았습니다. 앞서 확인한 HWPX 새 기본 템플릿 정규화 문제도 이번 버전 변경으로 해결된 것은 아닙니다.
