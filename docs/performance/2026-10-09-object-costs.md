# 그림·코드 박스 처리 비용 분석

[현재 Release 측정](2026-10-09-current-release.md)의 상세 계측 실행에서
`operation.figure/body`, `operation.code/code`, `operation.table/body` 범위에
속한 COM 이벤트를 다시 집계했습니다. 일반 Release 시간과 섞지 않았습니다.
분석 대상 소스는 `e03700a`이며 생성 코드는 변경하지 않았습니다.

| 처리 범위 | 개체 수 | 전체 시간(초) | 전체 XML 조회 수 | 전체 XML 조회 시간(초) | 직접 개체 삽입 시간(초) |
| --- | ---: | ---: | ---: | ---: | ---: |
| 그림 | 29 | 101.432 | 112 | 68.208 | InsertPicture 3.091 |
| 코드 박스 | 14 | 29.810 | 28 | 17.185 | 원형 InsertFile 0.792 |
| 표 임시 문단 | 39 | 5.826 | 0 | 0 | 실제 표 생성은 이 범위 밖 |

그림의 전체 XML 조회는 캡션 원형 복제 전후 58회(35.721초)와 출처 문단
복제 전후 54회(32.487초)입니다. 출처가 있는 그림 27개가 각각 두 번
조회했고, 출처가 없는 두 그림은 그 비용이 없습니다. 그림마다 캡션 복제를
두 번, 출처가 있으면 추가로 두 번 조회하여 거의 네 번씩 문서 전체를 내보냅니다.
코드 박스는 원형 복제 전후 각 한 번씩, 개체당 두 번 조회합니다.

전체 XML 조회만으로 그림 처리의 약 67.2%, 코드 박스 처리의 약 57.6%를
차지합니다. 이미지 파일 삽입 자체는 그림 처리의 약 3.0%입니다.
그림 캡션 원형의 InsertFile은 추가 1.670초, 출처 원형의 InsertFile은
추가 1.521초이며, 그림의 현재 문단 스타일 조사용 선택 XML 조회는 3.845초입니다.
따라서 단순히 그림 파일 삽입이나 개체 복사가 느리다고 설명할 수 없습니다.

## 왜 문서 전체를 조회하는가

`AuriMinimalCaptionPrototype.Insert`와 `AuriMinimalBoxPrototype.Insert`는
복제 전후 문서의 모든 루트 문단을 정규화하여 문자열 배열로 만들고,
삽입된 후보 문단 하나를 제외하면 이전 문서와 동일한지 확인합니다.
이 과정으로 새 원형의 문단 위치를 찾고, 다른 내용·개체·번호 제어문자가
변하지 않았는지도 검사합니다. `FigureSourcePrototype.Insert` 역시 복제 전후
전체 XML을 조회해 문단 수와 새 출처 문단 위치·원형 텍스트를 확인합니다.

즉 한 개체를 추가할 때마다 그 개체 외의 이미 생성된 내용까지 다시
내보내고 파싱·복사·대조합니다. 개체당 비용이 현재 문서 크기의 영향을 받습니다.
코드상 문서가 커질수록 누적 비용이 증가하는 구조이지만, 입력 크기별 증가율은
이번 한 크기의 로그만으로 확정하지 않습니다.

그림 처리 전체 시간과 계측된 COM 직접 시간의 차이는 약 20.741초,
코드 박스는 약 10.899초입니다. 여기에 XML 파싱·정규화·대조와 계측되지 않은
COM 속성 및 out/ref 메서드, 기록 비용이 포함됩니다. 세부 함수 계측이 없어
이 차이를 전부 정규화 비용으로 단정하지 않습니다.

## 표와의 비교에서 주의할 점

`RenderOperation`의 table 경로는 이 단계에서 표를 생성하지 않고
임시 문단을 입력합니다. 실제 행·셀·캡션·출처 구조와 열 너비는
`phase.attach-native`에서 XML로 조립하고, 공통 import 및 표 페이지 배치
검사는 `phase.import-native-references`에서 수행합니다.

따라서 개체당 그림 3.498초·코드 박스 2.129초·표 0.149초만 비교하면
각각 약 23배·14배 차이가 나지만, 표의 생성 비용 일부가 다른 단계에
있으므로 최종 개체별 전체 비용의 배수로 해석하면 안 됩니다.
현재 표 개별 조립·너비 계산 시간은 별도 계측되지 않았습니다.

## 다음 최적화 대상

복제 전후 커서 동작을 확인한 [좌표 추적 실험](2026-10-09-clone-position.md)이 있습니다.
실제 Release의 XML 조회를 제거하는 변경은 아직 하지 않았습니다.

그림·코드 박스의 복제 위치를 문서 전체 대조 대신 네이티브 커서 좌표와
삽입 전후 문단 변화로 추적하면, 이 두 처리 범위의 전체 XML 조회
140회와 관련 파싱·정규화 비용을 줄일 후보가 됩니다. 실제 생략 가능
횟수는 좌표 추적의 안정성을 검증한 뒤 결정합니다. 최종 저장·재열기
검증은 유지해야 합니다. 더 나아가 표처럼 XML에서 구조를 조립하는
경로를 검토할 수 있으나, 네이티브 개체·번호·캡션 서식 보존을 확인해야 합니다.

원시 집계는 `artifacts/performance-release-2026-10-09/object-costs.json`에
저장했고, 호출 근거는 같은 폴더의 `large.calls.csv`와 `large.spans.csv`입니다.
