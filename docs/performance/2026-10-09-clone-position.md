# 원형 복제의 좌표 추적 실험

[개체별 비용 분석](2026-10-09-object-costs.md)의 다음 후보인 복제 위치 추적을
Hancom 2020 11.0.0.9136에서 실험했습니다. 제품 코드와
`target/release`의 실행 파일·템플릿은 변경하지 않았습니다.
시험용 소스·백엔드·원고·로그는 `artifacts/clone-position-2026-10-09/`에 있습니다.
DESKTOP-BRTN48S\MOLIT의 Session 1, Windows PowerShell 5.1 x64 STA에서
순차 실행했고 기존 한글 프로세스·보안 모듈 검사와 RegisterModule을 유지했습니다.

## 관찰한 동작

`GetPos`는 화면 좌표가 아니라 리스트·문단·문자 오프셋을 반환합니다.
본문 끝의 빈 문단에서 `SetTextFile(block, "HWP", "insertfile")`을 실행한 경우
캡션·코드 박스·출처 문단 모두 다음 규칙을 따랐습니다.

| 시점 | 리스트 | 문단 | 문자 오프셋 |
| --- | ---: | ---: | ---: |
| 삽입 전 MoveDocEnd | 0 | n | 0 |
| 삽입 직후 | 0 | n | 0 |
| 삽입 후 MoveDocEnd | 0 | n + 1 | 0 |

XML에서 새 원형은 문단 n에 있었고, 루트 문단 수는 정확히 하나 증가했습니다.
삽입 직후 커서가 다음 빈 문단으로 자동 이동한다는 최초 가설은 틀렸습니다.
커서는 새 원형의 시작에 남으며, 명시적으로 MoveDocEnd를 실행해야
다음 빈 문단을 가리킵니다. 이 차이를 확인하고 반복 시험의 조건을 수정했습니다.

## 시험 결과

| 시험 | 캡션 | 코드 박스 | 출처 | 결과 |
| --- | ---: | ---: | ---: | --- |
| 기존 검증 원고 변환 중 좌표와 기존 XML 탐색 비교 | 4 | 6 | 2 | 12회 모두 삽입 전 문단 번호 = 실제 새 원형 문단 번호 |
| 빈 끝 문단에서 세 원형을 번갈아 반복 삽입 | 6 | 6 | 6 | 18회 모두 위 좌표·문단 수·대상 구조 규칙 일치 |
| 글자가 있는 끝 문단에서 반복 삽입 | 6 | 6 | 6 | 18회 모두 빈 문단 전제에서 제외 |

정상 변환 관찰에서는 기존 캡션·박스·출처의 전체 XML 검사와 위치 탐색을
그대로 유지했고, 그 결과와 좌표를 대조했습니다. 추가 반복 시험은
태그를 낮춘 동일 템플릿 XML을 사용하여 네이티브 HWP 원형을 직접 삽입하고,
매번 XML에서 루트 문단 수와 예상 위치의 TABLE·Figure AUTONUM·출처 텍스트를 확인했습니다.
같은 종류의 원형이 이미 존재하는 문서에서도 세 종류를 번갈아 삽입했습니다.

비어 있지 않은 문단에는 `끝 문단 α 😀 `를 입력했습니다. 문자 오프셋은 10이었고,
원형이 그 문단의 기존 글자 뒤에 합쳐졌습니다. 문단 번호 자체는 같았으나
순수한 빈 문단 복제로 취급할 수 없으므로 빈 문단 조건이 필요합니다.
본문 끝이 아닌 셀·머리말·꼬리말·각주 내부 삽입에는 이 규칙을 확장하지 않습니다.

## 실패한 초기 가설과 기록

첫 시험 코드는 GetPos의 반환값을 bool로 검사했으나 이 환경에서는
반환값이 없었습니다. 제품에서 이미 사용 중인 out 인자 방식으로 수정했습니다.
첫 정상 변환 관찰에서는 기존 생성·최종 저장·재열기 검증까지 완료한 뒤
추가 반복 시험에서 잘못된 최초 커서 가설 때문에 실패했습니다.
따라서 그 전체 시험 실행이 성공했다거나 결과 HWP가 발행됐다고 주장하지 않습니다.
관찰 로그는 보존하고, 수정된 반복 시험을 별도 실행하여 성공을 확인했습니다.

초기 기록은 attempt1/attempt2, 정상 변환 좌표는 render-positions.jsonl,
수정된 반복 시험은 stress-positions.jsonl 및 stress-run.json에 보관했습니다.
render-positions.jsonl의 MatchesEmptyTerminalRule은 최초 가설의 판정값이며
모두 false입니다. 수정된 규칙의 재집계는 summary.json의
RenderMatchesObservedRule=true, EmptyTerminalPass=18에 기록했습니다.
반복 시험은 13.334초에 성공했고, 원본 템플릿 SHA-256은 변경되지 않았습니다.

## 적용 가능 범위와 남은 검증

이번 템플릿의 본문 끝 빈 문단에서는 문서 전체 XML을 읽지 않고도
새 원형의 문단 위치를 추적할 근거를 얻었습니다. 적용할 때는 최소한
삽입 전 List=0·Offset=0, 삽입 직후 동일 위치, MoveDocEnd 후 문단 증가를
확인해야 합니다. 조건 불일치는 오류로 처리하고, 빈 문단을 몰래 추가하지 않습니다.

좌표 확인은 다른 문단·서식·개체가 보존됐음을 증명하지 않습니다.
실제 Release에서 전체 XML 조회를 제거하는 변경은 아직 하지 않았습니다.
적용 후에는 기존 Debug와 대규모 출력의 구조·이미지·페이지 비교를 다시 수행하고,
최종 저장·재열기 검증을 유지해야 합니다. 여러 템플릿·한글 버전에서 같은 동작을
보장하거나 실제 성능 단축을 측정한 시험도 아닙니다.
