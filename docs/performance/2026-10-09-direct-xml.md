# Release의 IR·템플릿 XML 직접 구성

같은 대규모 원고의 일반 Release 실행은 **209.830 → 121.349초**로 줄었습니다.
88.482초, **42.17% 단축**입니다. 기존 Debug와 새 Release의 구조·서식·내장 이미지 데이터,
107쪽 전체 RGB 픽셀이 일치했습니다. 모든 기능을 두 번 사용하는 작은 원고도
구조·서식·내장 이미지 데이터와 17쪽 전체 픽셀이 일치했습니다.

`52c05a4`는 문단·문자 서식, 목록, 코드 박스·그림 중간 원형을 XML에서 구성하는 기능과
계약 테스트입니다. `5d97050`은 이 구성기를 Release에 연결하며 앞 커밋에 의존합니다.
이 보고서는 두 커밋의 통합 결과를 기록합니다. 비교 대상 Release는
`55318d6` 시점이며, [직전 측정](2026-10-09-xml-comparison.md)과 같은 고정 입력을 사용했습니다.
IR 0.4와 템플릿 문법은 바뀌지 않았습니다.

## 생성과 검증의 경계

Debug는 기존 COM 문단 입력 경로를 유지합니다. Release는 검증된 IR와 처음 읽은 템플릿을
기준으로 평면 문서를 구성합니다. 일반 문단은 기존 StyleEx와 같은 STYLE 기본 문단·문자 모양을
사용하고, 원고의 강조·공백·탭·줄바꿈을 보존합니다. 목록은 템플릿의 네이티브 정의를 복제하되
원고의 시작 번호, 중첩 복귀, 항목 계속 문단의 들여쓰기를 유지합니다.

그림은 원본 PNG/JPEG 파일을 InsertPicture로 내장합니다. 캡션 원형을 한 번 네이티브 HWP로
복제해 본문·바탕쪽 개체의 할당 순서를 정리하고, 리소스 문서를 저장·재열기하여 이미지 캐시의
실제 크기를 확정합니다. 임시 캡션은 결과에 넣지 않습니다. 이 과정에서 얻는 정보는 내장 이미지,
네이티브 그림 속성과 개체 할당 순서입니다. 정적 내용과 원고 내용의 기대값은 원래 템플릿과 IR에서
가져옵니다. 코드 박스만 있으면 첫 박스의 네이티브 복제로 할당 상태를 얻습니다.

네이티브 복제는 서식 번호를 재배정할 수 있으므로 정적 내용·원형·목록의 서식 참조를 새 문서에
연결합니다. 정적 제어문자와 필드의 원래 식별자는 유지합니다. 새로 만드는 문자 모양만 한글의
직렬화 순서로 구성하며, 원래 스타일 정의와 비교 규칙은 수정하지 않습니다.

목록 계속 문단에 실제 번호 너비가 필요할 때만 구성 XML을 한글에 import하여 GetHeadingString으로
표시 번호를 측정합니다. 이 원고에는 두 항목이 해당합니다. 이 측정은 원고 내용을 다시 내보내
기대값으로 채택하는 작업이 아닙니다. 이후 제목 블록·각주·코드 제목과 출처·네이티브 캡션·표·참조를
붙이는 기존 처리와 최종 import 검사를 수행합니다. 최종 HWP 저장·재열기 후 전체 구조·서식·번호·필드·
페이지 검증에 성공해야 결과를 교체합니다.

CurrentParagraphStyle 자체의 조회 구현은 유지했습니다. Release가 대부분의 문단을 XML로 구성하므로
해당 조회를 문단마다 호출할 필요가 없어졌습니다. 최종 전체 문서 검사를 없애서 얻은 단축은 아닙니다.

## 확인 자료와 한계

대규모 원고는 5장·20절, 그림 29개, 코드 박스 14개, 표 39개, 각주 66개입니다.
작은 원고는 184개 루트 문단·각주 14개이며 모든 기능을 두 번 사용합니다.
그림 없는 코드 박스, JPEG 두 개, 개체 없는 Unicode 본문의 별도 입력도 최종 저장·재열기를 통과했습니다.
JPEG의 원본 바이트 보존이나 별도 Debug 픽셀 비교를 주장하지 않습니다.

독립 비교에는 이전부터 보관한 비교 바이너리를 사용했으며 최적화된 소스로 재빌드하지 않았습니다.
SHA-256은 `2c5abd79e1376ab26e3478a4ef1a11b951b65fd7fda4cbffb357154544767387`입니다.
이 비교는 서식 번호를 실제 정의로 해석하고, 개체·필드의 식별자 관계 및 전체 상대 겹침 순서를 검사합니다.
내장 데이터의 SHA-256과 PDF의 144dpi RGB 픽셀도 비교했습니다. HWP 파일 전체의 바이트 일치를
검사한 것은 아닙니다. 입력·이미지·템플릿·실행 파일 해시는 집계 JSON에 있습니다.

1·2·6·7·14·30·31·105쪽을 직접 확인했습니다. **기존 템플릿의 긴 표 문제도 확인했습니다.**
50행 표의 POSITION은 TreatAsChar=true이며 30·81쪽에서 후반 행이 잘립니다.
PDF 텍스트에도 지역 27–48이 나타나지 않습니다. 기존 Debug와 픽셀은 같으므로 이번 변경의 회귀는
아니지만, 출력 동등성이 배치 안전성을 뜻하지는 않습니다. 표의 글자처럼 취급·쪽 나눔 설정을 별도로
검토해야 합니다. 이번 성능 변경에서는 원본 템플릿을 수정하지 않았습니다.

첫 상세 계측은 초기 템플릿 import에서 기존의 간헐적인 `SIZE[142]/@Height: 4160 -> 2500` 검사에
실패했습니다. XML 구성에 들어가기 전의 실패이며 결과는 게시하지 않았습니다. 검사와 실패 로그를
유지한 채 재실행한 상세 계측은 성공했습니다. 이 기존 문제를 이번 최적화에서 무시하도록 바꾸지 않았습니다.

Rust workspace 테스트·Clippy, Debug/Release 백엔드 계약 테스트와 공식 빌드가 통과했습니다.
원시 증거는 `artifacts/performance-direct-xml-2026-10-09/`에 보관합니다.

- `complete/`: 최종 일반 실행, profile.json, 저장 XML·PDF·107쪽 이미지.
- `small-debug/`, `small-complete/`: 작은 원고의 기존 경로와 새 경로 비교.
- `large.detailed.json`: 호출·구간의 원시 시간선.
- `large.calls.csv`, `large.actions.csv`, `large.callsites.csv`, `large.spans.csv`, `large.xml.csv`: 액션·호출 위치·구간·XML 집계.
- `detailed-final/`, `failed-template-import.detailed.json`: 성공 계측과 초기 import 실패 증거.

다음 큰 후보는 네이티브 부착 단계 약 29초의 반복 서식 복사와 비교, import·재열기 양쪽의 표 페이지
검사, 그림 리소스 저장·재열기 약 15초입니다. 페이지 검사를 줄이려면 실제 clipping 검증을 먼저
정리해야 합니다. 그림 캐시 재사용도 네이티브 geometry와 저장 결과를 대조하는 실험이 필요합니다.

통합만 되돌리려면 `git revert 5d97050`을 사용합니다. 사용하지 않는 구성기와 계약 테스트도 제거하려면
그 뒤에 `git revert 52c05a4`를 적용합니다. 이 변경들은 로컬 커밋이며 원격 push는 하지 않았습니다.
