# Debug·Release 세 가지 생성 방식 비교

2026-10-09, 구현 커밋 `adbd437` 기준입니다. [기본 XML 구성 최적화](2026-10-09-direct-xml.md) 이후
Debug에서도 XML 구성을 기본값으로 사용하고, 기존 COM 삽입 경로는 `--legacy-com`으로 선택합니다.
IR·템플릿 규약은 바꾸지 않았습니다.

후속 `faa8dcf`에서는 상세 계측과 레거시 인자·안내를 Debug에만 컴파일하도록 바꿨습니다.
현재 측정 방식은 [Debug 전용 계측](2026-10-09-debug-profiling.md)을 따릅니다.
아래 수치와 설명은 당시 `adbd437`의 검증 기록입니다.

| 방식 | 백엔드 구성 | 옵션 | 추가 Debug 진단 |
| --- | --- | --- | --- |
| debug-com | Debug | `--legacy-com` | 유지 |
| debug-xml | Debug | 생략 | 유지 |
| release-xml | Release | 생략 | Release 검사 |

옵션은 Rust의 원고 변환·`ir2hwp`와 백엔드 직접 실행에서 전달됩니다. Rust 빌드와 별개로
선택한 백엔드의 구성이 지원 여부를 결정합니다. Release 백엔드는 파일 접근·COM 전에 거부합니다.
세 경로 모두 최종 저장·재열기 구조 검사를 유지합니다. Debug COM의 기존 생성 로직과
진단을 보존했습니다. 네이티브 복제·import의 Debug 추가 진단은 새 경로에도 적용하고,
기존 COM 삽입의 중간 저장·재열기 검사는 `--legacy-com` 경로에 유지합니다.

## 측정

같은 한글 2020, 사용자·세션·STA 호스트에서 문서를 순차 생성했습니다.
`MD2HWP_PROFILE=1`로 수집한 단일 실행이며 반복 측정 통계는 아닙니다.
대규모 Debug XML 실행 초기에는 작은 원고의 읽기 전용 비교 작업이 잠시 겹쳤습니다.
기능 원고의 debug-com은 Rust 원고 변환을 포함하고, 나머지는 백엔드를 직접 실행했습니다.
그 실행에서 생성된 IR의 SHA-256은 다른 두 방식에 입력한 추적 IR과 동일합니다.
백엔드 열은 C# 내부 생성 시간, 전체 열은 실행 파일 시작·종료까지의 시간입니다.
전체 XML과 스타일 블록 열은 프로파일에 기록된 export 호출 수입니다.

| 원고 | 방식 | 백엔드(초) | 전체(초) | 전체 XML export | 스타일 블록 export |
| --- | --- | ---: | ---: | ---: | ---: |
| 17쪽 | debug-com | 100.568 | 105.997 | 103 | 109 |
| 17쪽 | debug-xml | 48.611 | 49.072 | 19 | 1 |
| 17쪽 | release-xml | 33.224 | 33.546 | 14 | 1 |
| 107쪽 | debug-com | 500.710 | 501.159 | 386 | 473 |
| 107쪽 | debug-xml | 168.322 | 168.714 | 19 | 1 |
| 107쪽 | release-xml | 112.283 | 112.511 | 14 | 1 |

단계별 시간·횟수·내보낸 XML 크기, 실행 파일과 입력 해시는
[집계 JSON](2026-10-09-generation-modes.json)에 보관합니다. 중첩 단계 시간은 합산하지 않습니다.

## 출력 비교

17쪽 기능 검증 원고와 107쪽 대규모 원고 각각 세 쌍 모두 다음을 통과했습니다.

- 기존 비교 실행 파일을 변경하지 않고 문단·서식·제어문자·참조 대상 그래프를 대조했습니다.
- 내장 이미지 데이터가 일치했습니다.
- PDF를 144dpi RGB PNG로 렌더링한 전체 페이지의 모든 픽셀이 일치했습니다.
- 기능 원고 PDF 11쪽의 본문·강조·번호 참조·각주도 시각적으로 확인했습니다.
- 입력 IR·원고와 템플릿은 보존했습니다. 출력은 각 방식의 별도 경로에 저장했습니다.

문서 고유 식별자·저장 캐시 때문에 HWP 파일 자체의 바이트 일치를 요구하지 않습니다.
서식 번호는 참조된 정의를 풀어 비교하고, 개체 순서와 필드 대상은 기존 비교 규칙 그대로 검사합니다.
세 출력의 일치는 배치의 완전성을 보장하지 않습니다. 기존 긴 표 잘림은
[이전 보고서](2026-10-09-direct-xml.md)에 기록한 템플릿 조건을 그대로 따릅니다.

## 재현과 증거

[생성 방식별 실행 명령](../development.md#생성-방식-비교)을 사용하십시오.
Debug·Release는 `tools/development/build.ps1`로 빌드했습니다.
Rust 전체 테스트·Clippy와 백엔드 계약 테스트(Debug·Release)가 통과했습니다.
Release 옵션 거부와 Rust CLI의 실제 기존 COM 경로 전달도 확인했습니다.

원시 HWP, XML, PDF, 페이지 PNG, 프로파일·stdout·stderr 및 쌍별 비교 결과는
`artifacts/debug-generation-modes-2026-10-09/`에 보관합니다. 각 `small-*`·`large-*` 폴더에
`large.output.hwp`, `saved.xml`, `large.pdf`, `pages/`, `run.json`, `profile.json`이 있습니다.
이 원시 자료는 ignored이며, 집계 결과와 실행 안내는 추적합니다.
