# rhwp 목록 표식 실측과 후속 문단

기준일: 2026-10-22. HWP 전용 rhwp 백엔드의 여러 문단 목록 항목에 대한
구현 범위를 기록한다. IR 0.4, Markdown 문법과 템플릿 선언은 바뀌지 않는다.

## 동작

`UseInstWidth=false`는 표식의 기준 글자 크기와 native 거리 설정으로 계산하던
기존 동작을 유지한다. `UseInstWidth=true`는 항목 첫 문단의 실제 native 표식
문자열을 측정한 뒤, 표식이 없는 후속 문단의 본문 시작점을 맞춘다.
중첩 목록 뒤에 이어지는 같은 항목의 문단도 해당 항목의 표식을 사용한다.

실측은 문서 합성 후 수행한다. 표시 번호를 IR의 시작 번호와 항목 순서만으로
추정하지 않고, 합성된 문서의 native numbering ID별 카운터 이력과 시작값,
재시작·재개를 반영한다. 다른 번호 정의에서 돌아오면 그 정의의 이력을 복원한다.
`^1`–`^7`은 참조한 수준의 번호 형식을 사용한다. `^n`은 각 수준의 번호 형식과
관계없이 십진 숫자로 현재 수준까지 점으로 연결하며 `^N`은 끝의 점도 포함한다. 템플릿의 접두·접미 문자는 그대로 측정한다.

지원하는 번호 형식과 값의 범위는 다음과 같다. 범위 밖의 값이나 다른 native
형식은 대체 표시를 추측하지 않고 오류로 처리한다. 최종 표시값은 65535 이하여야 한다.

| Native 형식 코드 | 표시 | 지원 범위 |
| --- | --- | --- |
| 0 | 십진 숫자 | 0–65535 |
| 1 | 원 숫자 | 1–20 |
| 2, 3 | 대문자·소문자 로마 숫자 | 1–3999 |
| 4, 5 | 대문자·소문자 라틴 문자 | 1–65535 |
| 8 | 가, 나, 다 | 1–14 |
| 10 | ㄱ, ㄴ, ㄷ | 1–14 |
| 12, 13 | 한글·한자 수사 | 0–65535 |

## 측정과 단위

표식은 목록 샘플의 native 문자 서식을 사용한다. 실제 글꼴, 크기, 언어별
장평·상대 크기·자간과 굵게·기울임을 반영하며 자간은 grapheme 사이에만 넣는다.
측정은 안전한 `md2hwp-font-measurement` facade를 통해 Windows GDI의 4배
논리 크기로 수행한다. 표식 폭에는 표 셀 여백이나 표 폭의 1% 여유를 넣지 않는다.

후속 문단의 왼쪽 여백은 다음과 같다.

```text
left_URC + indent_URC
  + 2 × ties_to_even(marker_width_HWPUNIT + offset_HWPUNIT + width_adjust_HWPUNIT)
```

URC는 물리 길이를 두 배 정밀도로 저장하는 단위가 아니라 종류 비트가 있는 값이다.
공식 ParameterSet 표의 `HWPURC_MAKE` 정의에 따라 bit 0이 0이면 HWPUNIT 정수를
한 비트 왼쪽으로 옮긴 고정 길이이고, bit 0이 1이면 상대 문자 길이이며 나머지
비트에 문자 수의 100배가 들어간다. 근거는 저장소의
`reference/hancom-api/ParameterSetTable_2504.txt`의 URC 정의이다.
따라서 먼저 HWPUNIT에서 짝수 쪽 반올림을 수행한 뒤 2배하여 고정 길이를 인코딩한다.
원래 왼쪽 여백·첫 줄 들여쓰기가 홀수인 상대 문자 단위 입력은 명시적으로 거부한다.

거리 설정이 절대값이면 native 거리 자체를, 상대값이면 표식 기준 글자 크기에
백분율을 적용한 값을 `offset`으로 사용한다. 결과의 첫 줄 들여쓰기는 0이다.
단위를 두 번 변환하거나 반올림 뒤의 인코딩 순서를 바꾸지 않는다. 비정상 치수와 정수 범위
초과는 오류다. 후속 문단의 변경된 레이아웃 캐시만 비우며 native 표식·번호 정의와
주변 문서 구조를 유지한다.

## 기존 한글 백엔드의 단위 오류 수정

같은 계산을 사용하던 C# `NativeListContinuations.CalculateMargin`도 함께 수정한다.
기존 `Round(2 × x)`는 `x=2396.5`에서 홀수 URC 4793을 만들었다. 한글은 이를
고정 길이가 아닌 상대 문자 길이로 해석하여 HWPML에 `Left=24.0ch`로 내보냈다.
이로 인해 Direct XML 경로는 최종 검증에 실패했고, legacy COM 경로도 `24ch`를
정수 길이로 처리하다 `FormatException`을 냈다. 두 경로의 문제를 드러낸 실측
목록 시험을 계속하려면 공통 원인인 단위 인코딩을 바로잡아야 한다.

수정 후 C#과 Rust 모두 `2 × RoundTiesEven(x)`를 사용한다. 경계 회귀 사례는
2396.5→4792와 2397.5→4796이며, 상대 단위 입력도 양쪽에서 거부한다.
이 수정은 원고·템플릿 계약이나 최종 구조 비교를 완화하지 않는다. 수정 후
native 생성·재열기 및 페이지 비교 결과는 아래 검증 범위와 별도로 확인해야 한다.

## 명시적 제한

설치된 Windows TTF/OTF 글꼴이 필요하다. HFT, GDI의 다른 글꼴 선택, 선택한
글꼴에 없는 표식 글리프는 거부한다. 표식 글리프 확인은 `GetGlyphIndicesW`를
사용하므로 보조 평면 문자가 포함된 표식은 명시적으로 거부한다. 이미지 글머리표와
Unicode 사용자 영역 글머리표도 지원하지 않는다. 빈 표식과 제어문자가 포함된
표식, 7수준을 벗어나는 번호 참조도 거부한다. 지원하지 않는 경우 기존 한글
백엔드를 선택할 수 있으며 rhwp가 COM으로 자동 전환하지 않는다.

이 검사는 실제 폭을 재야 하는 native 목록 표식에만 적용한다. 일반 원고의
Unicode와 이모지는 기존과 같이 보존한다. 캡션·머리말·꼬리말·바탕쪽·주석·각주
안에서의 목록 후속 문단 실측은 지원하지 않는다. 기존 제목·그림·표 번호
상호참조는 계속 지원하며 이 목록 제한에 포함하지 않는다.

## 검증 범위

시험 원고는 `tests/fixtures/rhwp-list-widths.md`이다. 9→10, 99→100과 101로의
재개, 중첩 시작 번호, 여러 수준, 혼합 목록, 항목의 여러 후속 문단과 일반 본문
이모지를 포함한다. 추적 기본 템플릿에서 번호 목록은 `UseInstWidth=true`,
글머리표는 `false`이므로, 실제 폭 글머리표 검증에는 별도 템플릿을 사용했다.

수정한 기본 템플릿 시험은 한글 백엔드 `hancom-fixed.hwp`와 rhwp
`rhwp-fixed.hwp`를 각각 생성·재열기한 뒤 같은 한글 렌더러로 3쪽씩 출력했다.
`pixel-comparison.json`의 세 페이지 모두 차이 픽셀은 0이었다.
`GetHeadingString`으로 읽은 표식과 native 문단 여백을 독립 비교한
`marker-comparison.json`은 31개 레코드가 일치했다. 이 중 번호 표식은 14개이고
홀수 URC 여백은 없었다. 이 결과는 해당 원고와 템플릿의 표시·후속 문단 정렬에
대한 근거이며 모든 글꼴·번호 형식·페이지 구성을 포괄하지 않는다.

별도 형식 템플릿의 한글 출력에서 명시적 수준 슬롯의 `(RIX)`, `(RX)`,
`(RXCIX)`, `(RC)`와 `I-G.`, `I-H.`를 확인했다. 같은 시험에서 `^n`/`^N`은
수준별 로마·라틴 형식과 관계없이 `1.1.1`/`1.1.1.1.`처럼 십진 숫자로 표시됐다.
고정 upstream의 private 표시 함수와 다른 이 동작을 어댑터에 반영하고 회귀
검증을 추가했다. 수정 뒤 `variant-pixel-comparison.json`의 최종 양쪽 3쪽도 모두 차이 픽셀 0이었다.
`hancom-variant-markers.json`과 `rhwp-variant-fixed-markers.json`의 31개 레코드도
모두 일치했다. 중첩·혼합 형식이 있는 2·3쪽을 직접 시각 확인했다.

원래 전체 기능 원고도 rhwp의 엄격한 저장·재열기 검증을 통과해
`all-features-rhwp.hwp`로 생성됐으며 한글에서 13쪽으로 렌더링했다.
이 원고는 이번 시험에서 양쪽 페이지 픽셀을 비교하지 않았다.

형식 별칭 수정 뒤 workspace 테스트 247개(rhwp 132개, 글꼴 측정 3개 포함),
clippy와 fmt 검증이 통과했다. 최종 C# 계약 검증도 전체 통과했다. 최초 sandbox
실행은 PDF 출력 이동 권한 오류로 실패했으며, 승인된 승격 실행으로 다시 확인했다.
Debug `-Rhwp` 빌드가 완료됐고 원본 `templates/template.hwp`의 해시는 바뀌지 않았다.
단위 검증은 카운터 이력·재시작, 수준별 표시 형식, 단위·반올림 및 글꼴 실측의
오류 처리를 다룬다.

실제 폭 글머리표는 별도 `bullet-template.hwp`에 native U+25CF(●)를 명시하고
`UseInstWidth=true`로 시험했다. `hancom-bullet.hwp`와 `rhwp-bullet.hwp` 모두
엄격한 저장·재열기를 통과했고 `bullet-pixel-comparison.json`의 양쪽 3쪽은 모두
차이 픽셀 0이었다. rhwp의 3쪽 글머리표·후속 문단을 직접 시각 확인했다.
이 결과를 다른 글머리표·글꼴이나 명시적으로 거부하는 사용자 영역 표식까지
확대하지 않는다.

구현 커밋은 [9551c61: C# URC 수정](https://github.com/esnahn/md2hwp/commit/9551c61)과
[8286bf8: rhwp 목록 표식 실측](https://github.com/esnahn/md2hwp/commit/8286bf8)이다.

실행 산출물과 native 페이지·XML은 ignored `artifacts/rhwp-list-widths/`에 있다.
저장·재열기 구조 검증만으로 실제 들여쓰기·줄바꿈·페이지 배치의 정확성을
주장하지 않으며, 위에서 비교한 입력 밖의 실제 표시와 정렬은 별도 확인이 필요하다.
