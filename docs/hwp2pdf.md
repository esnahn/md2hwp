# HWP → PDF

`hwp2pdf.exe`는 기존 `.hwp`를 한글의 자체 PDF 출력 액션으로 변환합니다.
Windows x64, 한글, .NET 10 x64 런타임, 설치·등록된 한글 보안 모듈이 필요합니다.
[환경 준비](usage.md#사용자-환경)를 참고하십시오. 실행 중인 한글은 먼저 닫습니다.
HWPX는 지원하지 않습니다.

## 실행

```powershell
.\hwp2pdf.exe 원고.hwp
.\hwp2pdf.exe 원고.hwp 결과.pdf
.\hwp2pdf.exe 원고.hwp --output 결과.pdf
.\hwp2pdf.exe --input 원고.hwp --output 결과.pdf
.\hwp2pdf.exe --version
.\hwp2pdf.exe --help
```

출력을 생략하면 원본 옆에 같은 이름의 `.pdf`를 만듭니다.
예를 들어 `원고.output.hwp`는 `원고.output.pdf`가 됩니다.
위치 인자와 같은 역할의 옵션을 중복 지정하면 오류입니다.
명시한 상대 경로는 실행한 작업 폴더를 기준으로 해석합니다.
출력 폴더는 미리 만들어 두십시오. 성공하면 최종 PDF 경로와 종료 코드 0,
실패하면 오류와 종료 코드 1을 출력합니다.

`hwp2pdf.exe`에는 필요한 관리 어셈블리가 포함됩니다. 이 EXE 하나를 별도로
옮겨도 실행할 수 있으며, 별도 `md2hwp-backend.exe`, 템플릿, IR, Pandoc은
필요하지 않습니다. .NET 런타임은 포함하지 않습니다. 설치 위치가 별도라면
`DOTNET_ROOT_X64` 환경 변수에 런타임 폴더를 지정합니다.

## 출력 설정

[품질 조사](hancom-pdf-options.md)의 권장 조합인 `PrintToPDFEx`와
`GraphicQuality=100`을 고정 적용합니다. `Action.CreateSet`에서 얻은 세트는
같은 `Action.Execute`에 전달하며, 지정한 항목을 다시 읽어 적용 여부를 확인합니다.

- `Device=5`: 자체 PDF 출력. 프린터 스풀이나 외부 변환 도구를 사용하지 않습니다.
- `Range=6`, 연결 문서 제외: 현재 HWP 전체를 출력합니다.
- `PrintMethod=0`, `ZoomX=100`, `ZoomY=100`: 자동 인쇄, 100% 배율입니다.
- 그림·그리기 개체 포함, 한 부, 원래 페이지 순서로 출력합니다.
- 인쇄용 자동 머리말·꼬리말은 추가하지 않습니다. HWP 자체 머리말·꼬리말은 출력합니다.
- 해상도 등 그 밖의 설정은 해당 액션 기본값을 사용합니다.

시험한 한글 2020에서 그림은 JPEG 대신 Flate 압축으로 저장됩니다.
EMF의 벡터 유지나 원본 픽셀 일치를 보장하지 않으며, 그림 축소·색상 처리와
다른 한글 버전의 동작은 별도 문제입니다. 이 설정을 UI 품질 단계의 특정 이름과
동일하다고 단정하지 않습니다.

## 입력 그림 권장 해상도

PNG·JPG는 **문서에 최종 삽입할 크기를 기준으로 500dpi로 저장**하는 것을 권장합니다.
필요한 픽셀 수는 `삽입 크기(mm) / 25.4 × 500`이며, 예를 들어
142×79.875mm 그림은 약 **2795×1572픽셀**입니다. DPI 메타데이터와 함께
실제 픽셀 크기를 이 기준에 맞춥니다.

현재 한글 2020·권장 출력 설정의 [경계 시험](hwp2pdf-quality-matrix.md#해상도-경계)에서
500dpi 입력은 픽셀 크기를 유지했고 510dpi 이상은 약 500dpi로 축소됐습니다.
이 권장은 PDF 출력 단계의 추가 축소를 줄이기 위한 입력 준비 기준이며,
원본 픽셀 일치를 보장하지 않습니다. 프로그램이 입력 그림을 자동으로
500dpi로 바꾸지는 않습니다.

## 완료 확인과 원본 보호

원본 HWP는 읽어서 출력하며 저장하지 않습니다. 기존 한글 프로세스가 있으면
중단하며, 보안 모듈 등록·파일 확인과 `RegisterModule` 성공 후 문서를 엽니다.

출력 폴더 안에 고유 임시 폴더를 만들어 PDF를 생성하고 최대 5분 동안 파일
완료를 기다립니다. 이 대기는 출력 액션 반환 후에 적용되며 COM 호출 자체의
제한 시간이 아닙니다. 파일을 독점 읽기로 열 수 있고 PDF 헤더·최종 EOF·
교차참조 위치가 있으며 파일 크기가 연속으로 안정된 것을 확인합니다.
한글을 정상 종료하고 원본 해시가 그대로인 것을 확인한 뒤 임시 PDF를
최종 경로로 이동하여 기존 결과를 교체합니다. 실패하면 이전 PDF를 보존합니다.

이 검사는 PDF 파일의 완료 표식 검사입니다. 모든 PDF 개체의 유효성,
출력 페이지 수·본문·서체·화질·배치를 실행 중에 전부 검사하는 것은 아닙니다.
계약 테스트와 별도로 대표 문서의 구조·텍스트·페이지 이미지를 검토합니다.

## 한글 2020 실제 검증 — 2026-10-10

Windows x64의 사용자 대화형 Session 1, 한글 2020 `11.0.0.9136`에서
Debug·Release 게시 EXE로 차례로 변환했습니다. 원본 HWP의 해시는 그대로였고,
시험 후 한글 프로세스와 임시 출력 폴더가 남지 않았습니다.

| 문서 | 결과 |
| --- | --- |
| PNG·JPEG·EMF 세 종류를 포함한 5쪽 화질 문서 | Debug·Release 모두 5쪽, 539,051바이트. 그림 스트림은 Flate이고 JPEG DCT 스트림 없음 |
| A4·A3 두 구역 문서 | 2쪽, 21,550바이트. 페이지 크기 595×841pt·841×1190pt 유지 |
| 본문·제목·캡션·각주·참조가 있는 EMF 원고 | 9쪽, 274,583바이트. 본문·제목·각주의 한글 검색어 6개 모두 추출 |

전체 21쪽을 Poppler 90dpi로 렌더링했습니다. Debug·Release 화질 문서의
5쪽 RGB 픽셀은 모두 같았고, 화질·혼합 용지·원고의 전체 페이지 이미지를
검토했습니다. 원고에 원래 있는 첫 빈 페이지도 유지했습니다.

`hwp2pdf.exe` 하나만 있는 별도 폴더에서 9쪽 원고를 변환하여 단독 배포를
확인했습니다. 누락된 입력의 실패에서는 기존 PDF가 유지됐고, 정상 변환에서는
기존 결과가 교체됐습니다. 출력명을 생략한 경우와 옵션 순서 변경도 확인했습니다.
계약 테스트는 손상·미완성 PDF와 출력 파일 잠금에서 이전 결과가 유지되는지도 확인합니다.

`RangeIncludeLinkedDoc`은 이 버전의 실제 세트에 없고 SetItem 뒤에도 읽히지
않았습니다. 해당 항목은 지정하지 않으며, 공식 Print 명세에서 연결 문서를
제외하는 값인 `Range=6`을 사용합니다. 실행 시 지정하는 모든 항목은 읽기 확인을 통과했습니다.

원시 실행 기록·원본 해시·PDF 구조/텍스트 분석·전체 페이지 이미지는 ignored
`artifacts/hwp2pdf-2026-10-10/`의 `execution.json`, `analysis.json`,
`source-hashes.json`, `*-all-pages.png`에 보존했습니다.

일반·초고해상도와 490·500·510·590·600·610dpi 입력의 JPG·PNG·EMF 검증 결과는
[그림 품질·해상도 검증](hwp2pdf-quality-matrix.md)에 정리했습니다.
