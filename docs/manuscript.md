# 원고 작성

원고는 Unicode 텍스트로 작성합니다. 문단은 빈 줄로 구분하고, 문단 안의 일반 줄바꿈은 공백으로 합칩니다. 강제 줄바꿈은 줄 끝 공백 두 칸이나 역슬래시를 사용합니다.

- 본문: `**굵게**`, `*기울임*`, 글머리표·번호 목록을 지원합니다. 일반 링크는 표시문과 서식을 유지합니다.
- 제목: `#`~`######`를 사용합니다. 실제 개요 번호는 템플릿에서 설정하며, 제목만 작성해도 자동으로 생기지는 않습니다.
- 그림: 독립된 `![설명](image.png)`로 PNG·JPG·JPEG를 삽입합니다.
- 글상자: 코드 블록으로 작성합니다. 본문의 공백·탭·빈 줄은 보존합니다.
- 표: 머리행이 있는 파이프 표를 사용합니다. 캡션·정렬·제약은 [표 설명](tables.md)을 참고하십시오.
- 문서 정보: YAML의 `title`, `subtitle`, `author`, `date`, `publisher` 등을 사용합니다. [메타데이터](yaml-variables.md)와 [날짜 형식](date-metadata.md)을 참고하십시오.

문서 제목과 첫 장 제목은 별개입니다. 동봉 템플릿에는 YAML `title`이 필요합니다. 장 시작 번호는 `md2hwp-heading1-start`로 지정합니다.

## 각주

```markdown
본문에 각주를 붙입니다.[^설명]

[^설명]: 각주 안에서도 **굵게**, *기울임*, [링크](https://example.net)를 쓸 수 있습니다.

    들여쓴 다음 문단도 같은 각주에 포함됩니다.
```

참조 이름은 연결에 사용하며, 출력에는 한글의 실제 각주와 자동번호를 사용합니다.
같은 이름을 여러 번 참조하면 각 참조 위치에 각주가 생성됩니다. 본문·제목·목록·표 셀에서
각주를 사용할 수 있고, 각주 내용은 하나 이상의 일반 문단으로 작성합니다.
제목을 머리말·꼬리말·바탕쪽에 복제하는 템플릿에서는 해당 제목에 각주를 넣을 수 없습니다.
강조·링크·강제 줄바꿈을 지원하며 링크는 표기 텍스트로 출력합니다.
그림 설명·그림 및 표 캡션, 박스·그림·표 출처에서는 각주를 지원하지 않습니다. 각주 안의 중첩
각주, 제목·목록·그림·코드 블록 등 일반 문단 외의 블록도 지원하지 않습니다.
한글 2020의 실제 그림·표·코드 박스 캡션에서는 각주 삽입 동작이 거부됩니다.
표 출처는 캡션이 아닌 병합 셀이지만, 현재 개체 하단 설명 문법에서는 각주를
지원하지 않습니다. 검증 범위는 [캡션 내부 기능](caption-inlines.md)을 참고하십시오.
`^[내용]` 인라인 각주 문법은 활성화하지 않으며 각주로 해석하지 않습니다.

각주 문단 서식은 템플릿의 `{{md2hwp:footnote}}` 샘플에서 가져옵니다.
구분선·번호 모양·위치는 템플릿 문서의 한글 각주 설정을 따릅니다.
각주 검증 원고와 예상 IR은 [`examples/footnotes/`](../examples/footnotes/)에 있습니다.

## 번호 상호참조

```markdown
## 절 제목 {#section-one}

![대상지 현황](site.png){#site}

[그림 참조](#site)를 보십시오. [개요 참조](#section-one)를 참고하십시오.
```

Pandoc `xrefs_number`와 같은 내부 링크 문법을 사용합니다. 대상의 실제 종류로
헤딩·그림을 판별하며 `fig:`·`sec:` 접두사는 필수가 아닙니다. 링크 표시문은
템플릿의 번호 참조 표기로 대체합니다. 그림 참조의 장 번호는 대상 그림이 속한 장에서
계산하고, 그림 번호는 한글의 실제 상호참조 필드로 넣습니다. 개요 참조는 대상
헤딩에 설정된 한글의 실제 개요 번호를 참조합니다. heading1~heading6 모두 참조할 수 있습니다.
제목 스타일만 있는 문단은
개요 참조 대상이 될 수 없습니다. 표 번호 참조는 현재 지원하지 않습니다.

템플릿에는 `begin:ref.figure.number`와 `begin:ref.heading.number` 범위가
필요합니다. 기존 템플릿에 추가하거나 `init-template`으로 별도 템플릿을 생성하십시오.
문법·서식·지원 범위는 [번호 상호참조 설명](cross-references.md), 검증 원고와
IR은 [`examples/cross-references/`](../examples/cross-references/)를 참고하십시오.

### md2hwp의 제목·출처 규칙

다음 제목·출처 규칙은 CommonMark나 Pandoc 확장 문법에 포함되지 않는 md2hwp의 원고 규칙입니다.
표 캡션은 Pandoc Markdown 호환 문법을 별도로 연결합니다. 자세한 내용은 [표 설명](tables.md)을 참고하십시오.

- **`제목:`**: 코드 블록의 정확한 첫 줄에서만 사용합니다. 템플릿에
  `slot:code.title`이 있으면 접두어와 그 뒤 공백 한 칸을 제거하여 박스 제목으로
  출력하고, 바로 이어지는 빈 줄은 제거합니다. 제목 슬롯이 없으면 원문을 유지합니다.
- **`출처: 내용`**: 코드 블록·독립된 그림·표 바로 다음의 별도 문단으로 작성합니다.
  표 아래 캡션을 쓰면 그 캡션 다음에 출처를 둡니다.
  `출처:` 다음에는 공백과 내용이 필요합니다. 앞 개체의 출처로 연결하며,
  접두어 표기는 원고에서 보존하고 템플릿의 접두어·내용 슬롯에 넣습니다. 여러 하단 문단과
  추가 접두어는 [하단 설명 문법](object-sources.md)을 참고하십시오.

````markdown
```
제목: 건축물의 사용승인

제22조(건축물의 사용승인) ① 건축주가 …
  ② 허가권자는 …
```

출처: 국가법령정보센터
````

코드 블록의 본문은 한 줄마다 별도 박스 문단으로 출력합니다. 앞뒤 공백·탭과
본문 빈 줄을 보존하며, 남은 본문 안의 Markdown 문법이나 번호는 해석하지 않습니다.

### 문법 구현 세부

Markdown은 Pandoc의 `commonmark+yaml_metadata_block+footnotes+attributes+implicit_figures+pipe_tables`로 읽습니다.
CommonMark를 기본으로 하며 다음 다섯 확장을 사용합니다.

| 확장 | 용도 |
| --- | --- |
| `yaml_metadata_block` | 원고 맨 앞 YAML의 문서 정보·설정값 |
| `footnotes` | `[^이름]` 참조와 `[^이름]: 내용` 정의로 작성하는 각주 |
| `attributes` | 헤딩·그림의 `{#ID}` 수동 식별자 |
| `implicit_figures` | 독립 이미지를 Pandoc Figure로 해석 |
| `pipe_tables` | 파이프 표의 머리행·본문·열 정렬 |

CommonMark 요소 중 본문, 제목 1~6단계, 굵게·기울임, 링크, 강제 줄바꿈,
코드 블록, 글머리표·번호 목록, 독립된 PNG·JPG·JPEG 그림과 파이프 표를 지원합니다. 모든 CommonMark
요소를 출력하는 것은 아닙니다. 인용 블록, 인라인 코드, HTML 등 지원하지 않는
Pandoc 요소가 있으면 오류를 냅니다. 일반 문단의 원고 줄바꿈은 공백으로 합칩니다.
일반 링크는 서식 있는 표기 텍스트로 출력하며 자동 하이퍼링크를 만들지 않습니다.
목록 기호의 별도 글자 모양이 없으면 템플릿 목록 샘플의 글자 모양을 사용합니다.
항목 본문의 굵게·기울임은 목록 기호에 적용하지 않습니다.
같은 목록 항목의 둘째 이후 문단은 기호 없이 항목 본문 시작 위치에 맞춰 들여씁니다.

링크 뒤에 조사를 붙여 강조할 때는 `**[개요 참조](#section-one)는**`처럼
조사까지 강조 범위에 넣으십시오. `**[개요 참조](#section-one)**는`은 닫는
별표 앞의 `)`와 뒤의 조사 때문에 일반 별표로 해석됩니다.
이 경계는 [CommonMark의 강조 규칙](https://spec.commonmark.org/0.31.2/#emphasis-and-strong-emphasis)을 따릅니다.
번호 상호참조는 원고에서 참조가 놓인 위치의 글자 서식을 따릅니다. 본문·각주·표 셀의
서식과 굵게·기울임을 유지하며, 참조 원형은 문구와 번호 슬롯만 제공합니다.
그림·표 캡션과 코드·그림·표의 출처 및 하단 설명에서도 같은 번호 참조를 사용할 수 있습니다.
참조 필드 삽입을 마친 뒤 줄 배치를 다시 계산하고, 필드·서식·문서 구조가 보존됐는지
확인하여 저장합니다.

JPEG는 `.jpg`·`.jpeg` 확장자를 대소문자 구분 없이 지원합니다. 8비트 일반 순차
JPEG와 progressive JPEG를 지원하며 파일을 그림 개체로 내장합니다. PNG와 같이
템플릿의 최대 폭에 맞추고 픽셀 크기의 가로세로 비율을 유지합니다. 변환기 자체는
JPEG를 다른 형식으로 바꾸지 않지만, 한글은 저장하면서 이미지를 재인코딩하거나
동일한 이미지 데이터를 합칠 수 있으므로 원본 바이트 보존은 보장하지 않습니다.
[일반·progressive JPEG 검증 원고](../examples/jpeg/jpeg.md)를 참고하십시오.
