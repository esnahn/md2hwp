# IR 0.4 날짜 메타데이터와 fmt

v0.4.0 / IR 0.4의 날짜 계약입니다. 이전 IR 0.2에는 적용되지 않습니다.

## 입력과 저장

YAML `date`는 원고에 입력한 표시 문구를 보존합니다.
Rust core가 이 문구를 날짜로 인식하면 IR `metadata`에 `date-meta`를 추가합니다.
`date-meta`는 `YYYY-MM-DD` 형식의 문자열이며 사용자가 YAML에 직접 입력하는 키가 아닙니다.
Pandoc JSON에는 자동 생성되지 않으므로 AST→IR 변환에서 계산합니다.
C# 백엔드는 날짜 원문을 다시 파싱하지 않고 검증된 IR의 `date-meta`를 사용합니다.

예시:

```yaml
date: "2026년 10월 25일"
```

IR 메타데이터의 해당 부분:

```json
{
  "date": "2026년 10월 25일",
  "date-meta": "2026-10-25"
}
```

원문 보존은 YAML의 따옴표·들여쓰기 같은 소스 문법이 아니라 해석한 문자열의 표기를 보존한다는 뜻입니다.
기존 IR의 Unicode NFC 규칙은 유지합니다. 날짜 인식용 공백 처리가 원문 date를 바꾸어서는 안 됩니다.

## 지원 입력 형식

Pandoc 매뉴얼에서 설명하는 모든 date 형식에 아래 한국어·구분자 형식을 추가합니다.
표의 대괄호는 선택 부분을 설명하는 기호이며 원고에 그대로 입력하는 문자가 아닙니다.

| 입력 형식 | 예시 | date-meta |
| --- | --- | --- |
| `mm/dd/yyyy` | `04/02/2018` | `2018-04-02` |
| `mm/dd/yy` | `04/02/18` | `2018-04-02` |
| `yyyy-mm-dd` | `2018-04-02` | `2018-04-02` |
| `dd MM yyyy`, 영문 월 약어 | `02 Apr 2018` | `2018-04-02` |
| `dd MM yyyy`, 영문 월 전체 이름 | `02 April 2018` | `2018-04-02` |
| `MM dd, yyyy`, 영문 월 약어와 마침표 | `Apr. 02, 2018` | `2018-04-02` |
| `MM dd, yyyy`, 영문 월 전체 이름 | `April 02, 2018` | `2018-04-02` |
| `yyyy[mm[dd]]`, 연도 | `2018` | `2018-01-01` |
| `yyyy[mm[dd]]`, 연월 | `201804` | `2018-04-01` |
| `yyyy[mm[dd]]`, 연월일 | `20180402` | `2018-04-02` |
| `yyyy년 [m월 [d일]]`, 연도 | `2026년` | `2026-01-01` |
| `yyyy년 [m월 [d일]]`, 연월 | `2026년 10월` | `2026-10-01` |
| `yyyy년 [m월 [d일]]`, 연월일 | `2026년 10월 25일` | `2026-10-25` |
| `yyyy. m. d[.]` | `2026. 10. 25`, `2026. 10. 25.` | `2026-10-25` |
| `yyyy.m.d[.]` | `2026.10.25`, `2026.10.25.` | `2026-10-25` |
| `yyyy/m/d` | `2026/10/25` | `2026-10-25` |

[기본 형식의 근거](https://pandoc.org/MANUAL.html#variables-set-automatically)

- 구분자나 영문 월이 있는 형식은 월·일의 앞자리 0을 생략할 수 있습니다. 예: `4/2/2018`, `2018-4-2`, `2 Apr 2018`, `2026년 1월 2일`, `2026.1.2`, `2026/1/2`.
- 영문 월 약어는 뒤에 마침표가 있는 형태와 없는 형태를 모두 지원합니다. 월 전체 이름과 약어는 영어 기준입니다.
- 숫자가 연속되는 형식은 4·6·8자리만 허용합니다. `202612`는 2026년 12월이며 `2026년 1월 2일`로 추측하지 않습니다.
- 연도만 입력하면 월·일은 1월 1일, 연월만 입력하면 일은 1일로 보완합니다. 현재 날짜를 사용하지 않습니다.
- 두 자리 연도는 Pandoc과 같이 `00~68 → 2000~2068`, `69~99 → 1969~1999`로 해석합니다. chrono 기본 해석에 그대로 맡기면 경계가 다르므로 명시적으로 처리합니다.
- 구분자가 있는 숫자 연도의 세기 해석이 모호해지지 않도록 `yyyy`는 4자리, `yy`는 2자리로 구분합니다.
- 존재하는 양력 날짜를 검증합니다. 윤년을 반영하며 `2026-02-29`, 월 13, 일 0 등은 정규화하지 않습니다.

위 부분 날짜 보완과 2자리 연도 경계는 로컬 Pandoc 3.10.1의 `pandoc.utils.normalize_date` 실행으로 확인했습니다.
앞자리 0 생략 및 추가 한국어 표기 지원은 md2hwp의 확장 규칙이며 Pandoc과 같은 인식 범위라고 소개하지 않습니다.

## 인식 실패와 누락

날짜로 인식하지 못한 `date`도 표시 문구로 보존합니다. 예: `미정`.
이 경우 `date-meta`는 생성하지 않습니다. 날짜처럼 보이는 잘못된 값도 임의로 보정하지 않습니다.
`date`가 없으면 `date-meta`도 생성하지 않습니다.

템플릿에서 date만 사용하면 원문을 표시할 수 있습니다.
존재하지 않는 date-meta를 참조하면 기존 메타데이터 누락 규칙에 따라 오류를 냅니다.
오류에는 원문 date와 해당 태그 위치를 포함하여 입력 날짜를 고칠 수 있게 합니다.

## 템플릿 태그

```text
{{md2hwp:meta:date}}
{{md2hwp:meta:date-meta}}
{{md2hwp:meta:date-meta:fmt:%Y년 %-m월 %-d일}}
```

위 원고에서는 각각 다음을 표시합니다.

```text
2026년 10월 25일
2026-10-25
2026년 10월 25일
```

fmt는 정규화한 date-meta의 표시 형식을 지정합니다. date 원문을 바꾸지 않습니다.
`fmt:` 뒤에서 닫는 `}}` 앞까지를 서식 문자열로 읽습니다.
서식 문자열의 일반 문자는 그대로 출력하고 서식 지시자를 날짜 값으로 치환합니다.
태그가 여러 글자 서식 구간으로 나뉘어도 같은 문단 안에서 해석하며 첫 글자의 서식을 따릅니다.

| 지시자 | 의미 | 예: 2026-01-02 |
| --- | --- | --- |
| `%Y` | 네 자리 연도 | `2026` |
| `%y` | 두 자리 연도 | `26` |
| `%m` | 앞자리 0을 포함한 월 | `01` |
| `%-m` | 앞자리 0 없는 월 | `1` |
| `%d` | 앞자리 0을 포함한 일 | `02` |
| `%-d` | 앞자리 0 없는 일 | `2` |
| `%F` | ISO 날짜 | `2026-01-02` |
| `%%` | 문자 % | `%` |

fmt의 지원 지시자는 위 표와 같습니다.
알 수 없는 지시자, 빈 fmt, 제어문자를 포함한 서식은 오류로 처리합니다.
시간·시간대 등 date-meta에 없는 성분은 지원하지 않습니다.
fmt를 다른 메타데이터 키에 적용하는 기능은 이번 범위에 포함하지 않습니다.

서식 지시자는 [chrono의 날짜 서식 문법](https://docs.rs/chrono/latest/chrono/format/strftime/index.html)을 따릅니다.
Rust core의 날짜 유효성 검증에는 chrono를 사용하며,
백엔드의 표시 서식은 위 계약을 구현하여 Rust와 C#의 서식 문자열 차이가 사용자에게 드러나지 않게 합니다.

## 구현과 검증 범위

- 날짜 파싱은 Rust core에 둡니다. Pandoc 호출은 앱에 유지합니다.
- Rust의 IR 검증에서는 입력 date와 파생 date-meta의 관계도 확인합니다. 수동 IR에서 불일치한 값을 허용하지 않습니다.
- Rust는 date-meta의 ISO 날짜와 원문에서 계산한 날짜의 일치를 검증합니다. 백엔드는 원문 날짜를 다시 인식하지 않고 date-meta의 ISO 형식과 날짜 유효성을 검증합니다.
- 모든 입력 형식, 앞자리 0 생략, 연·연월 보완, 2자리 연도 경계, 윤년과 잘못된 날짜를 검증합니다.
- fmt 결과와 미지원 지시자·누락값 오류를 검증합니다.
- HWP에서는 태그 치환 뒤의 글자·문단 서식과 저장·재열기 결과를 확인합니다.

Rust 정규화·IR 스키마·C# 치환에 반영했습니다. 날짜 입력 인식은 Rust core가 담당합니다.
[YAML 메타데이터 문서](yaml-variables.md)에 연결되는 날짜 기능 계약입니다.
